Added a configurable graceful drain window and a `/drainz` endpoint on the engine health server. Set `server.drain_timeout` (seconds, default 10) in `domain.toml` to change how long shutdown waits for in-flight message handlers to finish before force-cancelling them. `POST /drainz` flips the engine to a new `draining` state distinct from `shutting_down`: the subscription poll loops stop pulling new batches while any batch already read finishes (no in-flight message is dropped), and the process stays alive so an orchestrator can quiesce it before sending SIGTERM. The outbox keeps flushing committed rows while draining, and partitioned subscriptions keep renewing their held leases so they are not abandoned mid-drain. While draining, `/readyz` reports not-ready (503) so a load balancer stops routing, while `/healthz` and `/livez` stay green. The engine warns if `drain_timeout` reaches the multi-worker Supervisor kill timeout, since a worker could be SIGKILLed before it drains.
