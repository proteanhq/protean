Added a configurable graceful drain window and a `/drainz` endpoint on the engine health server. Set `server.drain_timeout` (seconds, default 10) in `domain.toml` to change how long shutdown waits for in-flight message handlers to finish before force-cancelling them. `POST /drainz` flips the engine to a new `draining` state distinct from `shutting_down`: the engine stops taking new work while in-flight work finishes and the process stays alive, so an orchestrator can quiesce it before sending SIGTERM. While draining, `/readyz` reports not-ready (503) so a load balancer stops routing, while `/healthz` and `/livez` stay green. The engine warns if `drain_timeout` reaches the multi-worker Supervisor kill timeout, since a worker could be SIGKILLed before it drains.
