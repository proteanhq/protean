`protean verify` now reads the passed and failed test counts from pytest's final summary line. Before, it took the first `<N> passed` or `<N> failed` text anywhere in the output, so a failure message such as `port 15432 failed` or a `-ra` skip reason such as `0 passed on this platform` could replace the real counts in the `tests` stage. The pass or fail verdict was never affected: it comes from pytest's exit code.
