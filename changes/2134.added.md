`protean db init` creates the folder that holds one provider's schema migrations: `alembic.ini`, a two-line `env.py`, `script.py.mako` and an empty `versions/`. Plain `alembic -c migrations/alembic.ini ...` commands then load the domain and run on the provider's database, from any folder. A new `SCHEMA_MIGRATIONS` capability marks the providers that support migrations. The SQLite, PostgreSQL, MSSQL and MySQL providers declare it, and the memory and Elasticsearch providers do not. `BaseProvider.schema_migrator()` returns the provider's `SchemaMigrator` and raises `NotSupportedError` for a provider without the flag. The `postgresql`, `postgresql-psycopg2`, `sqlite`, `mssql` and `mysql` extras now install Alembic 1.13.0 or later. The command refuses an unknown provider, a provider without the flag, a provider with `managed = false`, a folder that exists and is not empty, and a missing Alembic (#2134)
