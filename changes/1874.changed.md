Under the mypy plugin, a class decorated with an element decorator is a subclass of its Protean base class, as it is at runtime. A decorated element is accepted wherever a signature names the base (`domain.cache_for`, `BaseCache.add`, `x: BaseValueObject = Money(...)`), `isinstance` narrows to it, base properties such as `state_` bind to it, and `super().__init__(...)` in a decorated domain service reaches the base. `BaseEntity` declares its fields keyword-only to type checkers, so mypy no longer reports "Attributes without a default cannot follow attributes with one". `@domain.query_handler` classes now get their base too. mypy may report new override errors where a field reuses the name of a base-class attribute with a different type.

**Migration:** [mypy sees decorated elements as subclasses of their base](https://docs.proteanhq.com/reference/migration/v0-18/#mypy-sees-decorated-elements-as-subclasses-of-their-base)
