A reconcile sweep that runs while a command is committing no longer makes that command fail. When the sweep found an outbox row missing after the command had appended its events but before it saved its outbox rows, the sweep wrote the row and the command's commit then failed on the outbox's unique `(message_id, target_broker)` index. The Unit of Work and the sweep now both write outbox rows with the new `BaseDAO.save_if_absent`, so whichever saves a row first keeps it and the other skips its copy. On Elasticsearch, which has no unique index, two writers that save the same row at the same moment can still both keep a row. `reconcile_outbox` and `protean outbox reconcile` now count only the rows the sweep wrote. A custom DAO gets `save_if_absent` from `BaseDAO`, which checks for the key and then saves, and can override it to handle a lost race.
