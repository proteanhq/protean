**Breaking.** A value object that no aggregate cluster places, such as one with no `part_of` that only projections hold, now appears in a top-level `value_objects` section of the IR. Its generated JSON Schema, Avro and Protobuf definitions carry its fields, and `protean schema generate` writes it to `schemas/value_objects/`, where `.proto` files import it. Its Protobuf full name moves from the holder's package to its own module's package, and two such value objects with the same class name now make `protean schema generate` fail. `protean ir diff` reports changes to it, and `protean check` reports `VALUE_OBJECT_MUTABLE_FIELD` and `DEPRECATED_ELEMENT` for it.

**Migration:** [Value objects outside every cluster get an IR section and schema files](https://docs.proteanhq.com/reference/migration/v0-19/#value-objects-outside-every-cluster-get-an-ir-section-and-schema-files)
