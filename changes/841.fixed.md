`protean ir diff` no longer calls an event's version bump upcaster-covered when an older stored version has no path to the new one. An event bumped v2->v3 with only a v2->v3 upcaster leaves its v1 payloads stranded, so changes riding on that bump stay breaking. This matches what the `UPCASTER_GAP` build-time check already reports. The same question is now asked of an event whose version did not move: deleting its upcaster strands the payloads that upcaster used to carry, so an aggregate replaying that event stays breaking. A bump that also moves the type string's base, as renaming the domain or the event class does, is not covered either: upcasters are registered under that base and a stored message is looked up by the base it was written with, so nothing can read the old payloads.
