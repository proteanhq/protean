**Breaking.** `protean ir diff` and the `protean-check-compat` hook report a new breaking change, `field_number_changed`, when an event keeps its `__version__` and a field it keeps gets a different Protobuf field number. Protean numbers Protobuf fields in sorted name order, so a `renamed_from` rename, or an added or removed field that does not sort last, moves the numbers of the fields after it. Such a rename used to be a safe `field_renamed`, and such an optional-field addition used to be safe. To fix it, bump the event's `__version__` and register an upcaster for the old version, which may return the payload unchanged. Commands, aggregates, entities, value objects and projections are not checked.
