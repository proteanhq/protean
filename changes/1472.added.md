Added a slice generator that promotes a slice-shaped IR fragment (ADR-0041) to the vertical-slice `ChangePlan` `protean add` writes: the aggregate, its command, event, command handler, projection, and projector. The fragment carries the element names, their fields (each an IR field entry), and the read-side wiring; the generator renders each field in its per-type declaration form and, when the read side is omitted, derives the default projection and projector from the event so an aligned write-side fragment (its command carrying the aggregate's fields, its event's non-id fields being aggregate fields) still passes `protean verify`. `protean add` now routes through the generator by building a default fragment from the name. The generator rejects a fragment it cannot render correctly: an element name, field name, or derived slug that is not a usable Python name; two of the slice's classes sharing a name, counting the read side the generator derives; a name that collides with a symbol the generated modules import or with a local they read back; a field name the framework or the generated code already uses; an unsupported field type; an event whose `<slug>_id` cannot hold the aggregate's id; an explicit projection not keyed on that field or carrying a field the event does not; an aggregate declaring the `<slug>_id` the event takes from its id; an identity key marked outside a projection; and a project whose composition root binds the domain to a name the generated code uses. `protean add` reports these as usage errors. The `protean new --from-model` parser will produce these fragments from parsed text.
