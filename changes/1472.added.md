Added a slice generator that promotes a slice-shaped IR fragment (ADR-0041) to the vertical-slice `ChangePlan` `protean add` writes: the aggregate, its command, event, command handler, projection, and projector. The fragment carries the element names, their fields (each an IR field entry), and the read-side wiring; the generator renders each field in its per-type declaration form and, when the read side is omitted, derives the default projection and projector from the event, so the slice still passes `protean verify`. `protean add` now routes through the generator by building a default fragment from the name. The generator rejects a fragment it cannot render correctly: an element name, field name, derived slug, package, or domain variable that is not a string, or is a string that is not a usable Python name; two of the slice's classes sharing a name, counting the read side the generator derives; a name that collides, in a module that carries it, with a symbol that module imports, or with a local the generated methods read back; a field name the framework or the generated code already uses; an unsupported field type; an event whose `<slug>_id` cannot hold the aggregate's id, or that bounds it while the aggregate declares its own `id`, in which case the id comes from the caller and a longer one is rejected when the event is raised; an explicit projection not keyed on that field or carrying a field the event does not; an aggregate declaring the `<slug>_id` the event takes from its id; an aggregate declaring `id` in a shape that cannot reach the event's surfaced reference, which holds a string; a write side that does not line up, where the command's fields are not the aggregate's, the event carries a non-id field the aggregate does not declare, or a field the aggregate shares with the command or the event is declared in a different shape on each, since the generated code reads each of those off the other and copies the value across unchanged; an identity key marked outside a projection; a field whose required flag is not the one ADR-0041 gives it (every authored field is required, the projection's key is not); a field whose `kind` and `type` do not pair the way ADR-0041 pairs them, or a `max_length` that is not a positive integer or that sits on a type taking no bound; and a project whose composition root binds the domain to a name that slice's generated code uses. `SliceFragment` takes an optional `slug` so a caller that already normalized the aggregate name passes the slug it computed. `protean add` reports these as usage errors. `SliceFragment.from_mapping` reads the nested mapping the `protean new --from-model` parser returns, so a parsed model promotes through the same generator; it rejects a key it cannot read at every level of that mapping, down to the keys of a field entry, rather than dropping it or reading it as a name it is not and promoting a fragment that says something else. The parser derives the aggregate's slug from the normalized class name the fragment carries, which is the one the generator derives from it, so the surfaced `<slug>_id` the parser demands is the one the generator looks for. It rejects the few aggregate names where that slug differs from the one `protean add` derives from the name as authored (`aB` gives the class `AB`, whose slug is `ab`, where `add aB` gives `a_b`), so the same name writes the same slice whichever surface authored it.
