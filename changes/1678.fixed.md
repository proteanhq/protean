The skills and the event handlers guide now teach one way for one aggregate to react to another aggregate's event. An event handler in the cluster that owns the event issues a command, and the other aggregate's command handler makes the change, skipping work it has already done so a redelivered event is harmless. The handler that listens on another cluster's stream, which `check` reports as `EVENT_HANDLER_FOREIGN_EVENT`, now appears only as a mistake to avoid.
