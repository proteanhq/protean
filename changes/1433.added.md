Materialized `raises` and `invokes` edges into the IR under a new `method_edges` key on the element that owns each method, and bumped the IR schema to v0.2.0. `raises` (on aggregates and entities) lists the events a method raises, derived by co-location: it can over-report (an event built but not raised is still listed) and under-report (an event built in a helper and raised through it is missed). `invokes` (on command handlers, event handlers, projectors, and process managers) lists the element methods a handler method calls, matched by name against the methods in scope. The match is receiver-blind: it can miss a call (an ambiguous name is skipped) and it can record a wrong edge (a unique name is recorded even when the real receiver is something else). Projector and process-manager scopes are aggregate and entity method names, so those two rarely carry a real edge. Both edges are read from the source as written, so treat them as an approximate guide to the domain's behavior. `protean ir diff` reports a changed edge once under the owning element, and a baseline stamped `0.1.0` now reports a version mismatch and must be regenerated.
