`protean ir diff` no longer downgrades an event's breaking changes to safe on upcaster coverage it has not earned. A bump is covered only when *every* version still in the event store reaches the new one, not only the version the old IR recorded: an event bumped v2 to v3 whose v1 to v2 edge was deleted strands its stored v1 payloads, and the diff now agrees with the build-time `UPCASTER_GAP` diagnostic about that instead of contradicting it. Coverage is also refused when the `__type__` string's base moved (an event class or domain rename), because the runtime chain is keyed by that base, so a stored message written under the old base resolves to no chain and no class whatever upcasters are registered under the new one.
