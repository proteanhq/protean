Fix the value and data modeling pattern pages so their examples run. The seven pages (replace primitives with value objects, validation layering, model reference data, track audit fields, temporal queries, multi-tenancy, and index aggregates for query paths) now take their code from `docs_src`, and tests check the behaviour each page describes. The multi-tenancy page passes a `Q` to `repo.find()`, calls `find_by()` with the `order_id` identity field, and shows that `TenantMiddleware` must run inside `DomainContextMiddleware`. Its `tenant_query` helper returns a query you can filter further. The temporal-queries page compares versions with `attributes()` from `protean.utils.reflection`. It says that `get()` inside a Unit of Work returns the cached instance only for an aggregate already passed to `repo.add()`, and that saving a temporal aggregate saves nothing. The validation-layering page checks the 24-hour cancel window with `timedelta`, because a `timedelta` has no `.hours` attribute. The model-reference-data page declares a shared-table model with `@domain.database_model(..., schema_name=...)`, because `Domain` has no `model` decorator. The index page gives `Outbox` and `Ticket` the fields their indexes name, and says how Protean's own `Outbox` indexes differ from the example: its unique index covers `message_id` and `target_broker` together.
