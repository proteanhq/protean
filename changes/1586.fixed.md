An aggregate with `identity_type = "integer"` now builds its model on the SQLAlchemy providers (SQLite, PostgreSQL, MySQL/MariaDB, MSSQL). Before, building it raised `TypeError: Integer() takes no arguments`. Under the `uuid` strategy an integer identity is a 128-bit number that no SQL integer column holds, so `Domain.init()` now raises `ConfigurationError` for that case. The message names the aggregate and the provider, and points to `identity_strategy = "function"` or `Auto(increment=True)`. The check also applies when the identifier sets `identity_type="integer"` or `identity_strategy="uuid"` itself. An identifier that sets `identity_type="integer"` on a domain whose `identity_type` is `string` used to save the number into a text column, and is now refused. The memory and Elasticsearch providers are unchanged.

**Migration:** [An integer identity under the `uuid` strategy is refused on SQL](https://docs.proteanhq.com/reference/migration/v0-18/#an-integer-identity-under-the-uuid-strategy-is-refused-on-sql)
