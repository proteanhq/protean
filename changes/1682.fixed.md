**Breaking.** A `ValueError` raised while a unit of work commits is no longer reported as a version conflict. Before, almost every such `ValueError` became `ExpectedVersionError`, with the outbox on or off, and a handler's version retry ran the handler again for it. It now raises `TransactionError` with the `ValueError` as its `__cause__`. This includes a `ValueError` from a sync event handler, which runs inside the commit. The memory and Message DB event stores' `append` and `_write` now raise `ExpectedVersionError` on a wrong expected version, where they raised `ValueError`. The memory store keeps the same message.

**Migration:** [A `ValueError` at commit is no longer reported as a version conflict](https://docs.proteanhq.com/reference/migration/v0-18/#a-valueerror-at-commit-is-no-longer-reported-as-a-version-conflict)
