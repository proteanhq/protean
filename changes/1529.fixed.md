The in-memory event store's `_read_last_message` now does a true descending tail read. It read the first 1,000 rows and took the last of those, so once a stream passed 1,000 records it returned a stale record instead of the newest one. The append-only recovery-checkpoint stream reaches that size over many restarts, so an event-store subscription's recovery rebuild could resume from an old checkpoint and re-read failed positions it had already resolved.
