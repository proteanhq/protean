**Breaking.** `protean schema generate --format protobuf` defines each value object and entity once, in its own `.proto` file. A file that uses one imports that file by its path under `schemas/` and names the type by its full name, such as `.shared.kernel.Money`. Before, every referencing file copied the message into its own package, so `protoc` rejected the tree with "already defined". Compile the files with `-I <output>/schemas`. A value object from another module keeps its own full name and is no longer copied into the referencing package. A value object with no file of its own, and entities that refer to each other, are defined as nested messages inside the file that uses them. Dates are written as `.google.protobuf.Timestamp`. The bytes on the wire are the same, but tools that compare message names see the new names. Schema generation in every format now fails with an error when two elements would be written to the same file, instead of overwriting one with the other. `generate_proto_schema()` gains a keyword-only `import_path` argument; called without it, it still returns one self-contained file.

**Migration:** [Generated `.proto` files import each other](https://docs.proteanhq.com/reference/migration/v0-19/#generated-proto-files-import-each-other)
