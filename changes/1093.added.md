`protean upgrade-check` now diffs a live `outbox` table for the two intra-0.16 structural migrations, emitting the exact SQL for your dialect: `OUTBOX_TARGET_BROKER_NULLABLE` when `target_broker` still allows NULL (backfill plus `SET NOT NULL`), and `OUTBOX_UNIQUE_INDEX_LEGACY` when the `message_id`-only unique index is still in place (the swap to the composite `(message_id, target_broker)` index the dual-write idempotency guard depends on). These shipped in 0.16.2 but were only ever on the release branch, so 0.17 would otherwise have offered fewer migration checks than the patch release before it. The v0.16 migration guide gains the matching recipes.
