**Breaking.** `protean ir diff` now gives each outcome its own exit code: `0` for no changes, `1` for breaking changes, `2` for a usage, load or config error, and `3` for non-breaking changes only. Before, `2` meant both "non-breaking changes only" and an unknown option, and `1` meant both breaking changes and every other error, so a CI gate could not tell a safe change from a broken run. Errors now print on stderr and leave stdout empty, including under `--format json`. The command checks its options before it reads `.protean/config.toml`. Under `strictness = "off"` it still loads both sides, so a bad command line or an IR that does not load exits `2`; when both sides load it exits `0` without comparing them. `ir check`, `ir show` and `protean-check-compat` keep their exit codes.

**Migration:** [`ir diff` exits 3 for non-breaking changes and 2 for errors](https://docs.proteanhq.com/reference/migration/v0-19/#ir-diff-exits-3-for-non-breaking-changes-and-2-for-errors)
