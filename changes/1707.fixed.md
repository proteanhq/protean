Six pattern pages now take their examples from files a test runs, and the teaching they got wrong is corrected:

- Projection rebuilds as deployment: `rebuild_projection()` replays events in its own process without a broker, so priority lanes do not apply to it. The page now says to run a large rebuild in a separate process, build the new projection beside the live one, and tune `batch_size`. The priority lanes concept page and the patterns index say the same.
- Projection granularity: the cache-backed dashboard projector reads through `view_for()` and writes through `cache_for()`, because a cache-backed projection has no repository. Shipping an order now lowers the pending count it raised.
- Running data migrations with priority lanes: the migration script reads customers one page at a time. A query returns at most 100 records by default, so the old script left every customer after the first 100 unchanged. Progress is read from `XINFO GROUPS` lag and pending counts, because `XLEN` counts every entry still stored, read or not.
- Message tracing: the test examples use `given(...).process()`, since the test DSL has no `.when()` or `.then_events()`. The FastAPI endpoint reads the `X-Correlation-ID` header with `Header()` and the request body with a Pydantic model.
- Eventual consistency in UIs: the TOML sets `event_processing = "sync"` at the top level, the FastAPI endpoints set `status_code=201` and answer 202 with a `JSONResponse`, and version polling stores the order's version on the projection, because a projection has no `_version` of its own.
- Testing event-driven flows: the inventory handler names the order stream with `stream_category`, because a handler that belongs to `Inventory` otherwise never receives `OrderPlaced`. The priority example uses `Priority.LOW`, since `Priority` has no `BACKFILL` member, and `handle_error` reads the message type from the message headers. The summary table now says test mode runs until every subscription is idle.
