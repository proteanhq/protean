Added an opt-in freshness path for a committed `llms.txt` domain snapshot, for agents that do not speak MCP. `protean docs generate --type=llms --check` renders the snapshot fresh in memory, compares it byte for byte to the committed file, writes nothing, and exits non-zero on drift (a missing file counts as drift). A new `[tool.protean.docs].domain_snapshot` config key, absent by default, names the snapshot path and the domain entry point, so `generate` and `--check` run with no repeated `--domain`/`--output` flags. Both values are read relative to the config file that declares them, so the commands name the same snapshot from every directory that finds the config: the one you run from and its two parents. MCP stays the recommended live surface; this is the documented secondary path with a stated staleness trade-off. Nothing is auto-installed by `protean new` or `protean dx`.
