`cache.get_ttl()` returns seconds on the Redis cache, where it returned milliseconds. The memory cache already returned seconds, and every other TTL on the port is seconds (the `TTL` config key, `add(ttl=...)`, `set_ttl()`), so the same call meant different things depending on which adapter was configured.

**Breaking (Redis cache only).** The value is 1000x smaller. Code that divided by 1000 to get seconds now divides seconds by 1000. Nothing inside Protean calls `get_ttl()`, so only your own callers are affected.

**Migration:** [`cache.get_ttl()` returns seconds on Redis, not milliseconds](https://docs.proteanhq.com/reference/migration/v0-17/#cacheget_ttl-returns-seconds-on-redis-not-milliseconds)
