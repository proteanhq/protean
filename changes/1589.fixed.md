The docs now name `IncorrectUsageError` as the exception an event-sourced aggregate raises when an event has no `@apply` handler. Four pages said `NotImplementedError`, which the framework never raises on this path. The `ES_EVENT_MISSING_APPLY` rationale now says the same thing. The Common Errors tables for aggregates and entities also name the right exceptions for instantiating an abstract class (`NotSupportedError`) and for raising an event from another aggregate (`ConfigurationError`).
