**Breaking.** The Redis broker's `dlq_inspect()`, `dlq_replay()`, `dlq_replay_all()`, `dlq_purge()` and `dlq_depth()` no longer treat every Redis `ResponseError` as an empty DLQ. A DLQ stream that does not exist still reads as empty, and a `dlq_id` that is not a Redis stream ID gives `None` or `False` without calling Redis. Any other `ResponseError`, such as `WRONGTYPE` for a key that is not a stream, reaches the caller.

**Migration:** [Some internal fallbacks let unexpected errors through](https://docs.proteanhq.com/reference/migration/v0-18/#some-internal-fallbacks-let-unexpected-errors-through)
