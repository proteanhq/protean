`get_ttl(key)` now answers the same three cases on every cache adapter: `None` when there is no such key, `math.inf` when the key exists and never expires, and the seconds remaining otherwise. Before this, the memory cache raised `KeyError` for a missing key and could never report a never-expiring key, while Redis returned its raw `PTTL` sentinels (`-2` absent, `-1` no expiry). An expired entry counts as absent on both adapters, so `get_ttl` returns `None` for it, the same way `get` does.

**Breaking (both cache adapters).** `BaseCache.get_ttl`'s signature changes from `-> float` to `-> float | None`. `BaseCache` is a Provisional API, so this lands in a minor release with no deprecation period. Nothing inside Protean reads `get_ttl`, so only your own callers are affected.

**Migration:** a memory-cache `except KeyError` around `get_ttl` no longer fires; check `is None` instead. A Redis `ttl < 0` sentinel check no longer fires; check `is None` for an absent key and `== math.inf` for a never-expiring one. See [`get_ttl` returns None or math.inf instead of a raw sentinel](https://docs.proteanhq.com/reference/migration/v0-18/#get_ttl-returns-none-or-mathinf-instead-of-a-raw-sentinel).
