Custom subscription profiles can now be defined under `[server.profiles.<name>]` in `domain.toml`. A custom profile is a set of subscription config overrides, optionally basing itself on a built-in profile with `inherits = "<built-in>"` (single level onto a built-in base). Once defined, a custom profile name is usable wherever a built-in name is: a per-handler `profile`, a handler's Meta `subscription_profile`, or `default_subscription_profile` (which resolves below the server-level defaults, so those still win over its fields). Validation is fail-fast, raising `ConfigurationError` when a custom profile reuses a reserved built-in name, sets an unknown field, or inherits from anything other than a built-in.
