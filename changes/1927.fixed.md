**Breaking.** `protean schema generate` now types the values of a `Dict(value_type=ValueObject(...))` field. JSON Schema refers to the value object from `additionalProperties`, Avro writes a `map` of the value object's record, and Protobuf writes a `map` whose value type is the value object's message. Each format still defines the value object once when another field also uses it. A value object that only a `Dict` field uses now joins its aggregate's cluster in the IR, so the generators write its fields and `protean ir diff` compares them. A Protobuf reference to a value object whose name ends in `Entry` is written by its full name, so it cannot resolve to the hidden entry message `protoc` creates for a map field. The IR records the value object's full name as `target` on the `Dict` field, so the IR schema moves to `0.4.0` and every committed IR baseline must be regenerated. An untyped `Dict()` keeps its old output.

**Migration:** [The IR schema is now v0.4.0, and schemas type a `Dict` of value objects](https://docs.proteanhq.com/reference/migration/v0-19/#the-ir-schema-is-now-v040-and-schemas-type-a-dict-of-value-objects)
