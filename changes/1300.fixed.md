Fixed `protean new`, which generated projects that could not start. The scaffolded `domain.toml` wrote environment substitutions unquoted (`secret_key = ${SECRET_KEY|...}`), which is not valid TOML, so **every** generated project failed to load its own config. It also wrote keys no adapter reads: `redis_url` and `ttl` instead of `URI` and `TTL` for the Redis broker and cache, `host`/`port`/`username`/`password` instead of `database_uri` for Elasticsearch, `provider = "sqlalchemy"` (not a registered provider) for the SQLite, PostgreSQL and MSSQL sections, `provider = "redis-pubsub"` instead of `redis_pubsub`, and a stray `database` key that SQLAlchemy rejected. New tests generate a project for each choice and initialise its domain, which is what the previous text-only assertions never did.
