Added `protean recover --verify-checkpoints`, a read-only check for the window a backup restore leaves behind. When a checkpoint stream is backed up after the category stream it tracks, a restore can leave a subscription's checkpoint pointing past the head of the restored stream, so the subscription would skip every event in between. The command reports each event-store subscription whose checkpoint is strictly ahead of its stream head, prints a table (or `--json` result envelope), and exits `1` when any checkpoint is beyond head, `0` when all are consistent. A fresh subscription (checkpoint `-1`) and a caught-up one both read as consistent. Only event-store subscriptions track checkpoints, so broker and stream subscriptions are not examined.
