Added a [Tuning Subscriptions](https://docs.proteanhq.com/guides/server/tuning-subscriptions/) guide covering everything the 5.2 work shipped: choosing a subscription profile, overriding a single setting versus defining a custom profile, capping stream growth with `retention_maxlen`, what the circuit breaker does when a handler keeps failing, processing events for one entity in order with `sequential_by`, and reading consumer lag from the CLI or the readiness probe. It also says which knob to reach for first when a subscription is not keeping up. The `dlq_retention_hours` and `dlq_alert_threshold` options are now listed in the server configuration reference, and a test keeps every subscription option and profile documented.
