**Breaking.** A `ValueError` raised while a unit of work commits is no longer reported as a version conflict when the outbox is off. It now raises `TransactionError`, the same as with the outbox on, and a handler's version retry no longer runs the handler again for it. Only Message DB's `P0001` wrong-expected-version error still becomes `ExpectedVersionError`. The memory event store's `write` now raises `ExpectedVersionError` on a wrong expected version, where it raised `ValueError`, with the same message.

**Migration:** [A `ValueError` at commit is no longer reported as a version conflict](https://docs.proteanhq.com/reference/migration/v0-18/#a-valueerror-at-commit-is-no-longer-reported-as-a-version-conflict)
