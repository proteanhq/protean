**Breaking.** A Unit of Work saves a state-based aggregate's events only once `repository.add()` has saved the aggregate in that transaction, as it already did for an event-sourced aggregate. Before, reading a state-based aggregate inside a Unit of Work was enough: events raised on it were written to the event store and the outbox at commit, while its field changes were not saved, so the stored event recorded a change the database never got. Events raised on an aggregate that was only read are now not saved at commit, with no warning and no error. Code that reads an aggregate, calls a method that raises an event and never calls `add()` must call `repo.add()` after the change to keep the event.

**Migration:** [State-based aggregates save their events only through `add()`](https://docs.proteanhq.com/reference/migration/v0-19/#state-based-aggregates-save-their-events-only-through-add)
