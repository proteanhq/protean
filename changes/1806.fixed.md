A process on Python 3.11 that held stored messages until exit no longer risks a segmentation fault at shutdown. Pydantic gives a datetime parsed from an offset string, such as `"2024-01-02T03:04:05Z"`, pydantic-core's own `TzInfo` class, and freeing one while Python 3.11 tears its modules down could crash the interpreter. Datetimes that Protean parses now carry an equal `datetime.timezone` instead: `DateTime()` fields, message header `time` and `deadline`, the memory event store, the outbox, and consume-idempotency records. The instant and its UTC offset are unchanged. Only the `tzinfo` object's class differs, so `type(value.tzinfo) is datetime.timezone` now holds where it did not before.
