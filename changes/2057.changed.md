**Behaviour change.** The memory event store keeps its messages in its own list and writes each message at once, outside any Unit of Work, as Message DB does. A message appended while a Unit of Work is active, such as a command a handler issues before it fails, now survives the rollback. Before, the append joined the Unit of Work and the rollback discarded it. The domain no longer registers the internal `MemoryMessage` aggregate and its repository for the store, and `get_connection()` on the memory store returns the stored rows instead of `None`.

**Migration:** [A memory event store write survives a Unit of Work rollback](https://docs.proteanhq.com/reference/migration/v0-19/#a-memory-event-store-write-survives-a-unit-of-work-rollback)
