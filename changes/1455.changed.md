**Breaking.** String and Text fields no longer sanitize by default: the `sanitize` default flipped from `True` to `False`, so a field declared without an explicit `sanitize=` kwarg now stores the raw input instead of running `bleach.clean()` on it. Sanitization is a display-layer concern, so encode output where it is rendered; pass `sanitize=True` for a value rendered as HTML without output encoding. A new `[field_defaults] sanitize` config key sets the default for a whole domain (precedence: field kwarg > domain default > framework default); a malformed value is rejected at config load with `CONFIG_INVALID_FIELD_DEFAULTS` rather than read as "do not sanitize". `protean upgrade-check --opportunities` enumerates every String/Text field that relied on the old default once you are on 0.18.0.

**Migration:** [String and Text no longer sanitize by default](https://docs.proteanhq.com/reference/migration/v0-18/#string-and-text-no-longer-sanitize-by-default)
