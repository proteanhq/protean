Documented Protean's versioning policy, and simplified it. Protean does not use strict semantic versioning; it follows the same shape as SQLAlchemy, where the minor position is where breaking change lands, patches never change API, and majors are reserved for a categorical shift rather than accumulated breakage. The contract is that code running warning-free on 1.N runs unmodified on 1.N+1. The old fixed survival windows (two minors for a rename, three for a behavioural flip) are gone: every deprecation already declares the version it will be removed in, which is more precise than a blanket count, and the only fixed rule is that a removal is never in the same release as its deprecation. A new [versioning policy](https://docs.proteanhq.com/reference/versioning-policy/) page states the contract and how to enforce it in your own CI.
