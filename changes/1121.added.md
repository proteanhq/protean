`protean check` now detects every active framework-API deprecation. A declarative deprecation registry in `protean._deprecation` is the single source of truth: each framework-API warn site routes through `warn_from_registry`/`deprecated_from_registry`, which read the removal version and replacement advice from the entry, so a framework deprecation cannot warn without being registered (a source-scan test enforces it; a user-declared deprecated event is the one exception, since its removal comes from the event's own meta). New check rules close the static-detection gap — `DEPRECATED_CONFIG` flags a non-default `email_providers` config block, `DEPRECATED_IMPORT` flags deprecated `Method`/`Nested` serializer fields and `protean.utils.*` plumbing imports (on-disk source scan of modules that host a registered element), and a `pickled=` argument on `List` now surfaces as `DEPRECATED_FIELD`. The four imperative email/testing helpers that have no static call site stay covered by their per-version `DeprecationWarning`. A registry-driven audit test enforces the coverage.
