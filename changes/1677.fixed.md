Every Python example not marked as a fragment in the command-handler, event-handler, application-service, domain-service, add-domain-service-flow, repository and message-enrichment skills now runs, and `check` finds no warning or error on their assets, apart from the completeness findings a one-concept example is expected to raise, such as an aggregate without a command handler or an event nobody handles. A domain service flow persists one aggregate per handler. The other aggregate changes through an event and a command, in the skills, the domain services guide and tutorial chapter 13. The skills now say what the Unit of Work does: it can hold several aggregates, a nested one joins the outer one, and a version conflict re-runs the whole handler, up to 4 runs in total with the default `server.version_retry` settings. They say commit and rollback are atomic on providers with real or simulated transactions, such as the SQL databases and the in-memory provider, and never on Elasticsearch. They no longer claim that a public domain service helper raises `RecursionError`, or that leaving out `super().__init__()` unwires invariants. The command handler and event handler option tables list every option with its default, and message-enrichment covers `@domain.aggregate_enricher`. Its audit example, and the matching examples in the message enrichment guide and the audit fields pattern, skip aggregates without the audit fields, so they no longer fail on the records Protean saves through repositories, such as outbox rows and the in-memory event store's message records.
