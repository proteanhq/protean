A `print()` call or an early log line in a domain module no longer reaches stdout when a CLI command loads the domain. While a command such as `check`, `verify`, `upgrade-check`, `ir show` or `events catalog` imports, initializes or checks the domain, or builds its IR, anything the domain's modules or a custom lint rule write through `sys.stdout` goes to stderr. The pre-commit hooks and the MCP server's `introspect`, `check` and `validate` tools do the same. The JSON output and the IR a command prints on success now parse cleanly, a command with an error envelope prints only that envelope, and an `ir diff` or `upgrade-check` that fails to load the domain leaves stdout empty. This also covers #2024, where an import-time structlog line reached stdout from `ir diff`, `ir show`, `ir check` and `schema show`. `protean shell`, `server` and `observatory` keep the domain's output on stdout.
