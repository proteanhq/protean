Fix the configuration, logging and server reference pages so their examples match what Protean does. The eight pages (configuration, logging, and the server configuration, hardening, observability, sequential-by, subscription types and supervisor references) now take their code from `docs_src`. Tests load each example. Most tests check the behaviour the page describes; a few only check that a TOML example parses to the values shown. Two known bugs are recorded as strict expected failures: `redact = []` turns log redaction off, and the per-handler `dlq_retention_hours` and `dlq_alert_threshold` overrides under `[server.subscriptions]` are not applied. The configuration page uses `database_uri` where it said `database_url`, and its broker examples no longer show a `TTL` key. The `critical_streams` examples in the logging guide and the FastAPI wide-events guide use patterns that match full message types such as `Orders.PlaceOrder.v1`. The server configuration page lists a handler's Meta `subscription_type` above its `subscription_profile`, which is the order Protean applies them in. It gives the defaults a domain resolves to with no settings (`event_store`, 100 messages per tick), and explains that `default_subscription_profile` only fills fields the server defaults leave unset. It also says that an unknown subscription type logs a warning and falls back to `event_store`, and that `enable_dlq` is turned off for an event store subscription. Neither raises an error, though the page used to say both did. The subscription types page shows the real position record and the real dead letter message, with its metadata under `_dlq_metadata`, and says the event store subscription retries failed positions in a periodic recovery pass. The sequential-by process manager example starts from a `PaymentConfirmed` event, so each category uses one partition key. The observability page lists every metric the `/metrics` endpoint emits when OpenTelemetry is off, and the monitoring guides and tutorials use the metric names Protean emits: `protean_subscription_consumer_lag`, `protean_subscription_pending_messages` and `protean_outbox_pending_count`.
