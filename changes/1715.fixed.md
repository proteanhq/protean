The observatory skips a malformed trace entry and keeps reading the rest. Before, these entries could fail a trace endpoint or stop the live trace stream:

- a payload that is not a JSON object;
- a payload that is not valid UTF-8, on `/traces`;
- a `worker_id` that is not a string, in the worker throughput chart;
- an integer longer than 4300 digits, or very deep nesting, in the live trace stream.

A `duration_ms` that is infinite or NaN is left out of the latency figures. Before, it made the trace stats and overview endpoints answer 500.
