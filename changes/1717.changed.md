**Breaking.** An element given a non-dict positional argument now raises `TypeError` instead of `AssertionError`. The message still says the argument must be a dict. This covers aggregates, entities, value objects, commands, events, queries, projections, process managers and emails, and the entity helper `_update_data`. A field's `renamed_from` given a value that is not a string, list or tuple now raises `TypeError` instead of `ValueError`; an empty or non-string alias inside the list still raises `ValueError`. Code that caught the old exception types should catch `TypeError`.

**Migration:** [A non-dict positional argument raises `TypeError`](https://docs.proteanhq.com/reference/migration/v0-18/#a-non-dict-positional-argument-raises-typeerror)
