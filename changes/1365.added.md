Added `protean eventstore dlq replay` and `protean eventstore dlq purge` to act on an exhausted event-store position. `replay` re-drives the failing event through its handler once (recording a resolution and exiting 0 on success, or reopening the position for the recovery pass and exiting 1 on a repeat failure) without moving the subscription read cursor; `purge` appends a terminal `Purged` marker that clears the position and survives a rebuild. Replay confirms first, naming the target (an event handler, a projector, or a command with or without an idempotency key) and warning that it re-runs handler side effects; it refuses a command whose deadline has passed. Both commands re-read the position's latest status right before they act, so a position another replay or purge cleared while the prompt was open is refused. Use `--handler` to pick one when a position is exhausted in more than one handler on the same stream.
