Removing a field from an event-sourced aggregate can now be earned safe by declaring the field name in `reserved` on the aggregate (`@domain.aggregate(event_sourced=True, reserved=["note"])`). The declaration does the migration: during replay only, an assignment to a reserved name (from a retained `@apply` handler for a retired event) is dropped instead of raising, so the aggregate still rebuilds. The live `raise_` path still raises on a write to a removed field, and reusing a reserved name for a live field raises `IncorrectUsageError` at registration. `protean ir diff` downgrades the `field_removed` change to safe, cited `reserved`, when the aggregate is event-sourced on both sides and the removed name is reserved; a type change, a newly required field, and the replay hazards stay breaking.

**Migration:** [Removing a field from an event-sourced aggregate needs `reserved`](https://docs.proteanhq.com/reference/migration/v0-18/#removing-a-field-from-an-event-sourced-aggregate)
