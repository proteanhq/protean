Added a machine-checked TLA+ specification of the aggregate optimistic-concurrency no-lost-update protocol, `specs/OCC.tla`, alongside the existing checkpoint and outbox specs. It models two concurrent writers committing to one aggregate as a single atomic compare-and-set (advance the stored version to `base + 1` only if it is still the base, else raise `ExpectedVersionError`), the faithful abstraction of both shipped fixes: the SQL `version_id_col` guard (#1087) and the Memory `MemorySession` compare-and-set (#1258). TLC checks the safety invariants (`NoLostUpdate`, `AtMostOneWinnerPerBase`) and liveness exhaustively over every interleaving of two writers; an `Atomic` constant toggles a split compare-then-write revert that TLC refutes on `NoLostUpdate`, and an `OCC_conflict.cfg` probe witnesses that the two writers genuinely contend. `specs/README.md` maps each invariant to the "No lost update" guarantee in `docs/reference/guarantees.md` (ADR-0013). Design-time verification, not a CI gate.
