**Behavioural break, synchronous processing only.** Under `event_processing = "sync"`, an `ExpectedVersionError` raised by an event handler no longer reaches the caller unchanged. It used to trigger the command handler's version retry, which ran a command whose writes were already saved and saved them a second time. The caller of `domain.process()` now gets a `TransactionError` with the `ExpectedVersionError` as its `__cause__`, and under `command_processing = "sync"` the command runs once. When version retry is enabled, an event handler's or projector's own retry inside `@handle` still retries its conflict. A conflict in one handler class no longer stops the other handler classes for the same event; when several fail, the `__cause__` is an `ExceptionGroup`. A conflict on the command's own writes still raises `ExpectedVersionError` and is still retried when version retry is enabled.

**Migration:** [A synchronous event handler's version conflict no longer reruns the command](https://docs.proteanhq.com/reference/migration/v0-18/#a-synchronous-event-handlers-version-conflict-no-longer-reruns-the-command)
