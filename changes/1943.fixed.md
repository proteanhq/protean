The `EmailAddress` value object in a project that `protean new` generates raises a `ValidationError` for an address without `@`. Before, `shared/value_objects.py` checked the address in `__post_init__`, which Protean never calls on a value object, so it accepted any string. The check is now an `@invariant.post` method that raises `ValidationError` with the message under `email`. The same file's `Money` now stores `amount` as `Decimal`, so `add` and `subtract` give exact results, and both raise `ValidationError` with the message under `currency`, in place of `ValueError`, when the currencies differ. A project generated earlier keeps its own copy of the file and does not change.
