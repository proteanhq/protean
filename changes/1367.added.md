Event-store subscriptions now report how far behind they are in seconds, not just in message count. `SubscriptionStatus` carries a new `lag_seconds` field: `0.0` when caught up, the wall-clock gap since the last processed position when lagging, and `None` when the seconds cannot be computed (no timestamp, or lag itself is unknown). The seconds flow through every surface the message-count lag already reaches: the `Lag (s)` column and `--json` output of `protean subscriptions status`, the `/readyz` subscription details, the `protean.subscription.lag_seconds` OTel gauge (unit `s`), and the `protean_subscription_lag_seconds` hand-rolled Prometheus fallback. A missing value is reported as unavailable, never as `0.0`, so it can never read as "caught up".
