`protean db migrate` and `protean db check` now match each table by its schema and its name. A custom database model with its table in a second schema, such as `__table_args__ = {"schema": "reporting"}`, is compared in that schema. Before, autogenerate reported such a table as missing and created it a second time, and it dropped an unrelated table of the same name in the provider's schema. `protean db check` names the table `reporting.archive`. A raw index is looked for in the schema of its table. The migration runs the raw index's DDL as written, so for a table in a second schema the DDL must name that schema, as in SQLite's `CREATE INDEX reporting.ix_archive_title ON archive (title)`. On SQLite, the downgrade of a table copy re-creates each index in the schema of its table. A SQLite table copy drops the index it rebuilds by its qualified name, `main.<index>` in the default schema, so an index of the same name in an attached database stays. A SQLite foreign key to a table in another attached database is not compared, because SQLite cannot store one. For a provider in the default schema, the only change in output is that qualified `DROP INDEX IF EXISTS main.<index>`.
