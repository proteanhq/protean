`protean ir diff` now reports a field removed from an event-sourced aggregate as safe. An event-sourced aggregate holds no stored schema of its own: its state is a stream of events plus an optional snapshot, and the snapshot is a rebuildable cache that Protean discards and replays past when the schema has moved. The aggregate must be event-sourced in both snapshots, since a classic aggregate converted to event sourcing stored its old state as table rows that replay cannot rebuild. A field type change and a new required field are still breaking: a stored snapshot can survive a type change and skip replay entirely, and replay runs no required-field check. The downgrade makes no claim that replay still works; the changes that stop it are reported separately as their own breaking changes.
