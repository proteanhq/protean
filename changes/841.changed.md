`protean ir diff` now downgrades an event-sourced aggregate's breaking field removal or required-field add to safe when one of the events that rebuilds it has an upcaster-covered version bump and no rebuilding event is left with a breaking payload change. Replay rebuilds the aggregate, so those changes are earned-safe on the same terms as the events that replay it. An uncovered bump, a payload change made without a bump, or no bump at all leaves the aggregate breaking, and so does a covered bump on an `@apply` handler added in the same diff, which never rebuilt historical state. A field type change stays breaking: a stored snapshot can still hold the old value in a shape the new field accepts, so the aggregate loads from that snapshot and never replays through the upcaster. A classic table-backed aggregate is never touched by this path; `exclude` stays the only escape hatch there.
