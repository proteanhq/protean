`protean ir diff` now downgrades an event-sourced aggregate's breaking field removal to safe when one of the events that rebuilds it has an upcaster-covered version bump and every rebuilding event whose payload changed is covered too. Replay rebuilds the aggregate, so the removal is earned-safe on the same terms as the events that replay it. An uncovered bump, a payload change made without a bump, or no bump at all leaves the aggregate breaking, and so does a covered bump on an `@apply` handler added in the same diff, which never rebuilt historical state. A rebuilding event that lost a field under the deprecation grace counts as uncovered: stored payloads still carry that field and the event rejects them, so replay cannot start. The payload question is answered from the event's fields in the two snapshots, so it also catches a change the checker reports nothing for, such as an existing field turning required. A field type change stays breaking, because a stored snapshot can still hold the old value in a shape the new field accepts, so the aggregate loads from that snapshot and never replays through the upcaster. A new required field stays breaking too, because replay runs no required-field check and nothing in the IR shows whether an `@apply` handler assigns the field. A classic table-backed aggregate is never touched by this path; `exclude` stays the only escape hatch there.
