The eight event design and integration pattern pages now take their code from `docs_src`, and tests run every example that is not marked `# fragment`. Fixing them corrected these examples:

- Fact Events as Integration Contracts: the subscriber created a `ShippingProfile` with only `customer_id` while `full_name` and `email` were required, and it failed when a customer had no shipping address. The Fulfillment and Analytics subscribers now read the snapshot from `payload["data"]`, where Protean publishes it. The page no longer says snapshots can arrive in any order: without a version check, an older snapshot that arrives late overwrites a newer one.
- Sharing Event Classes Across Domains: the publisher contract test called `order.items.add(...)`, which does not exist. It now calls `order.add_items(...)`. The consumer contract test passed a payload with fields the consumer's class does not declare, which raised `ValidationError`. It now keeps only the declared fields. The pattern diagram no longer lists `total` on the Fulfillment class.
- Event Versioning and Evolution: the event-sourced aggregate examples now declare real fields in place of a `# ... fields ...` placeholder, and replaying an `OrderPlaced` event now sets the order's identity. The tolerant reader no longer claims to accept extra fields, which a typed event rejects.
- Publishing Events to External Brokers: the configuration now sets `server.default_subscription_type = "stream"`. Without it, the outbox is off and no rows reach the external brokers. The consumer now matches the event type exactly, so `OrderShippedLate` no longer creates a shipment.
- Consuming Events from Other Domains: the schema-change and error-handling subscribers now ignore event types other than `OrderPlaced`. A note says the page reads flat payloads, and where a Protean producer puts the fields.
- CloudEvents Interoperability: the two-service example called `broker.receive(...)`, which no broker has. It now reads with `broker.get_next(...)`.
- Message Enrichment: the inventory handler now sets `stream_category` to the order stream. A handler that belongs to `Inventory` does not otherwise receive `OrderPlaced`. The enricher module now imports `g`, the middleware imports `uuid4`, the problem list names the aggregate's `place()` method, and the order aggregate defines the `add_item` and `_validate_can_place` methods the page's tests call.
