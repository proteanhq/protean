The eight event design and integration pattern pages now take their code from `docs_src`, and tests run every example that is not marked `# fragment`. Fixing them corrected these examples:

- Design Events for Consumers: the subscriber used `channel=` and `@handle`. It now uses `stream=` and `__call__(self, payload)`, and reads the event fields from `payload["data"]`, where Protean publishes them.
- Fact Events as Integration Contracts: the subscriber created a `ShippingProfile` with only `customer_id` while `full_name` and `email` were required, and it failed when a customer had no shipping address. The Fulfillment and Analytics subscribers now read the snapshot from `payload["data"]`, where Protean publishes it.
- Sharing Event Classes Across Domains: the publisher contract test called `order.items.add(...)`, which does not exist. It now calls `order.add_items(...)`. The consumer contract test passed a payload with fields the consumer's class does not declare, which raised `ValidationError`. It now keeps only the declared fields.
- Event Versioning and Evolution: the event-sourced aggregate examples now declare real fields in place of a `# ... fields ...` placeholder.
- Publishing Events to External Brokers: the configuration now sets `server.default_subscription_type = "stream"`. Without it, the outbox is off and no rows reach the external brokers.
- Message Enrichment: the inventory handler now sets `stream_category` to the order stream. A handler that belongs to `Inventory` does not otherwise receive `OrderPlaced`. The enricher module now imports `g`, the middleware imports `uuid4`, and the order aggregate defines the `add_item` and `_validate_can_place` methods the page's tests call.
