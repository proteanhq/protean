**Breaking.** `reconcile_outbox` and `protean outbox reconcile` no longer publish an event of a state-based aggregate whose relational commit rolled back. The unit of work appends events to the event store before it commits the aggregate row and its outbox rows, so a failed commit left the event in the store while the aggregate's change and its outbox rows were not saved. Reconcile rebuilt the outbox rows, and consumers, including external brokers for a `published` event, were told about a change that was never saved. Reconcile now repairs only events of event-sourced aggregates, and skips every state-based aggregate's event whether or not its row exists. On a provider that keeps writes without a transaction, such as Elasticsearch, a lost outbox row behind a saved aggregate row is no longer repaired.

**Migration:** [Outbox reconciliation repairs only event-sourced aggregates' events](https://docs.proteanhq.com/reference/migration/v0-18/#outbox-reconciliation-repairs-only-event-sourced-aggregates-events)
