**Breaking (response shape).** The engine's `/readyz` probe now reports `checks.subscriptions` as an object instead of a bare integer. It carries `total` plus a `details` row per subscription with lag, pending count, DLQ depth, status, and circuit-breaker state, using the same field names as `protean subscriptions status`. Anything reading `checks.subscriptions` as a number needs updating. The FastAPI health router is unchanged and still omits the field.

The block is informational and never changes the probe's verdict: a lagging subscription or an open circuit breaker still returns `200`, because a backlog is not a reason to pull a pod out of service. It is gathered by a background task every two seconds rather than on the probe path, so answering `/readyz` still costs nothing and a slow or hung backend can never delay or fail readiness. The block reports `collection_pending`, `collection_error`, or `stale` with an `age_seconds` when the data is not current.

**Migration:** [`/readyz` reports an object where it reported a number](https://docs.proteanhq.com/reference/migration/v0-17/#readyz-reports-an-object-where-it-reported-a-number)
