`String`/`Text` fields now enforce their length bounds (`min_length`, `max_length`, and a required field's implicit minimum) on the *sanitized* value, and `choices` fields are no longer sanitized. Previously, sanitization (`bleach` — HTML-escaping grows a value, comment/attribute stripping shrinks it) ran after the bounds were checked on the raw input, so a within-bounds input could be stored out of bounds — or a `choices` value could be escaped so it no longer matched its own choice list — and re-validating that stored value on a serialization round-trip or event-sourced replay failed, leaving the aggregate unreplayable. Such input is now rejected at write time with a clear message; widen the bound or set `sanitize=False` if you need the escaped form. See ADR-0026.
