Add stream retention for StreamSubscriptions: the new `retention_maxlen` config field caps a subscription's broker stream so it does not grow without bound. After each batch the stream is trimmed, and the trim is consumer-progress-safe — with more than one consumer group the Redis broker trims by `XTRIM MINID` at the slowest group's last-delivered position, so an entry a slow group has not read is never removed (a plain `MAXLEN` is used only when there is at most one group). Trimming is approximate and size-based (no time-based TTL), off by default, and each built-in profile carries a default cap (`production`/`fast` 100,000, `batch` 500,000, `debug` 1,000, `projection` none). Custom `[server.profiles]` sections may set `retention_maxlen` too. Brokers without a persistent stream (inline) treat `trim()` as a no-op.
