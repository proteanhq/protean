`protean check --format json` and `protean verify --json` now emit one shared, versioned result envelope (`{version, status, data, diagnostics}`) with a pinned JSON Schema, and both commands adopt one exit-code convention (`0` success, `1` a detected failure, `2` usage/environment error, `>=3` command-specific) that new commands can converge onto. `check`'s exit codes collapse (any findings failure is now `1`, not `1`-error-vs-`2`-warning; load/config errors move from `1` to `2`) and `verify`'s shift up by one (`2` usage, `3` init, `4` check, `5` tests). Machine output keeps stdout to the envelope alone, with errors and logs on stderr, even when a domain logs while it loads; and `check --format json` is never filtered by `--level` (that flag now only shapes the human view), so a `status="fail"` envelope always carries the diagnostics that caused it. This is a pre-release correction, not a break; see the [v0.18 migration guide](https://docs.proteanhq.com/reference/migration/v0-18/).
