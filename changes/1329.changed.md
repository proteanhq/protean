`protean check --format json` and `protean verify --json` now emit one shared, versioned result envelope (`{version, status, data, diagnostics}`) with a pinned JSON Schema, and both commands follow one CLI-wide exit-code convention (`0` success, `1` a detected failure, `2` usage/environment error, `>=3` command-specific). `check`'s exit codes collapse (any findings failure is now `1`, not `1`-error-vs-`2`-warning; load/config errors move from `1` to `2`) and `verify`'s shift up by one (`2` usage, `3` init, `4` check, `5` tests). Machine output keeps stdout to the envelope alone, with errors and logs on stderr. This is a pre-release correction, not a break; see the [v0.18 migration guide](https://docs.proteanhq.com/reference/migration/v0-18/).
