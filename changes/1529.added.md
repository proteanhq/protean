`protean recover --verify-checkpoints` now also flags recovery-tracking entries a restore left past the stream head: an event-store subscription's recovery pass keeps a `recovery-checkpoint` snapshot and a `failed-positions` stream of positions to retry, and a rolled-back category stream can leave those naming positions the restored store no longer holds, which the recovery pass would retry forever. `--reset-beyond-head` clears those stale entries so the recovery pass stops chasing them.
