`protean recover --verify-checkpoints` now also flags recovery-tracking entries whose message a restore removed: an event-store subscription's recovery pass keeps a `recovery-checkpoint` snapshot and a `failed-positions` stream of positions to retry, and a restore can leave those naming a message the restored store no longer holds (it rolled the category stream back, or removed the specific aggregate stream a position points at). The recovery pass would re-read each, find nothing, and retry it forever. `--reset-beyond-head` clears those stale entries so the recovery pass stops chasing them. A restore that instead leaves the checkpoint watermark ahead of the failed-positions stream it references is reported as `unknown` (unverifiable): the failed stream reuses positions after such a truncation and cannot be reconstructed reliably, so the command reports the inconsistency and the reset leaves it untouched.

`protean subscriptions status --json` (and the Observatory subscription payload) now carry two more event-store fields alongside `position_stream`: `recovery_checkpoint_stream` and `failed_positions_stream` (both `null` for broker, stream, and outbox subscriptions).
