**Breaking.** A query that filters a `DateTime` field compares instants on every provider, so a filter value in another UTC offset returns the right rows. The memory provider compares two datetimes as UTC instants in `exact`, `in`, `lt`, `lte`, `gt`, `gte`, `any` and `overlap`, where it used to compare their string form. On SQLite, MySQL, MariaDB and SQL Server, a `DateTime` column now stores UTC: each value is converted to UTC before it is written or compared, and a load returns a UTC-aware `datetime` instead of a naive one. On memory and on these four databases, a naive value is read as UTC. The column definitions and PostgreSQL storage are unchanged. Rows written before the upgrade with a non-UTC offset keep their old wall-clock value.

**Migration:** [Datetimes are compared and stored as UTC](https://docs.proteanhq.com/reference/migration/v0-18/#datetimes-are-compared-and-stored-as-utc)
