A new `sql` event store keeps events on a SQLite file or a PostgreSQL database through SQLAlchemy, with no database extension. Set `provider = "sql"` and a `database_uri` in `[event_store]`, and call `create_schema()` to create its `messages` and `snapshots` tables. It declares `PRODUCTION | SCHEMA_MANAGEMENT`: a category lock and a unique constraint keep the expected-version check safe for concurrent writers, and on PostgreSQL the lock key matches Message DB's `hash_64` of the category. It does not support consumer groups. In-memory SQLite and isolation levels that break the version check raise `ConfigurationError`. A `tests/adapters.toml` conformance entry can now be a table with a `config`, so one adapter runs the conformance suite on more than one database (#2042)
