A new `sql` event store keeps events on a SQLite file or a PostgreSQL database through SQLAlchemy, with no database extension. Set `provider = "sql"` and a `database_uri` in `[event_store]`. `protean db setup` and `domain.setup_database()` create its `messages` and `snapshots` tables, and `protean db drop` drops them. It declares `PRODUCTION | SCHEMA_MANAGEMENT`. A write takes a category lock before the expected-version check, and a unique constraint on `(stream_name, position)` turns a write that skipped the lock into `ExpectedVersionError`. On PostgreSQL the lock key is Message DB's `hash_64` of `"<schema>.messages:<category>"`. It does not support consumer groups. In-memory SQLite and isolation levels that break the version check raise `ConfigurationError`. `protean eventstore verify` now reads the snapshot of each stream with a `-` in its name, other than snapshot streams, when `$all` does not return it. A `tests/adapters.toml` conformance entry can now be a table with a `config`, so one adapter runs the conformance suite on more than one database (#2042)
