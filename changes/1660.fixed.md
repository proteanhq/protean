With priority lanes on and the Redis Streams broker, an idle subscription no longer logs `broker.redis.read_blocking_failed` every 5 seconds or holds up its backfill lane. When the primary stream was empty, its non-blocking check sent `BLOCK 0` to Redis, which means "wait forever". The read hung until the client's socket timed out, so the backfill lane was served at most once every 5 seconds. `read_blocking(timeout_ms=0)` on the Redis broker now returns at once. A `blocking_timeout_ms` of `0` now polls Redis with no wait, which keeps an idle subscription busy on a full CPU core, so keep the default unless you have a measured need.

**Breaking.** On the Redis broker, `read_blocking(timeout_ms=0)` used to wait until a message arrived. It now returns at once. A subscription with `blocking_timeout_ms = 0` now polls continuously instead of waiting, and a negative `timeout_ms` is logged as a read failure.

**Migration:** [A zero read timeout on Redis no longer waits](https://docs.proteanhq.com/reference/migration/v0-18/#a-zero-read-timeout-on-redis-no-longer-waits)
