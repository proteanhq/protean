Fixed an order-dependent flake in the Message-DB test suite. All Message-DB tests share one Postgres `message-db` database, whose `$all` stream tail and per-stream version counters are global to the process, so residue from an earlier test could skew a later `$all`-tail read and fail intermittently only when the full matrix ran in one process. An autouse fixture now truncates the shared store before every `message_db`-marked test, so each test starts clean and no test depends on execution order. This does not affect the framework itself, only test isolation.
