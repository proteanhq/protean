**Breaking.** Every element that takes a single `part_of` now checks the kind of element it names. An entity accepts an aggregate or an entity; an event or command an aggregate or a process manager; a database model an aggregate, an entity or a projection; a query or query handler a projection; a value object, application service, repository, event-sourced repository, command handler or event handler an aggregate. A domain service's list of aggregates is unchanged. A class of the wrong kind raises `IncorrectUsageError` when the element registers. The message names the element, the target and the kinds it accepts, except for a repository, which keeps its existing "can only be associated with an Aggregate" message. An entity is also rejected when tied to an abstract aggregate, by class or by string. Before, a value object, application service, database model, event or command tied to the wrong kind registered without complaint, and most other wrong targets failed later with an `AttributeError`, `TypeError` or bare `AssertionError`. An event handler, command handler, application service or database model tied to a process manager also registered before and is now rejected. A query or query handler tied to a class that is not a projection now fails at registration, not at `domain.init()`. A string `part_of` resolves against the same kinds, so an entity can now name a parent entity by string, an event or command can name a process manager, and an event-sourced repository's string `part_of` works. When an aggregate and a process manager share a name, the string resolves to the aggregate. An entity chain that loops back on itself now fails `domain.init()` with `ConfigurationError`; the class form used to hang.

**Migration:** [`part_of` must name the right kind of element](https://docs.proteanhq.com/reference/migration/v0-18/#part_of-must-name-the-right-kind-of-element)
