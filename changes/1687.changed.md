With priority lanes on, a stream subscription that is idle now waits on the primary and the backfill stream in one read. A production message that arrives during the wait is picked up at once. Before, the subscription waited only on the backfill stream, so a production message could wait up to 1 second. Brokers gain a `read_blocking_streams` method that reads several streams in one call and returns the messages keyed by stream. The Redis broker serves it with one `XREADGROUP` call, and other brokers fall back to reading the streams one at a time.
