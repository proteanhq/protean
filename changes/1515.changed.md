`protean new` now ships a dx-managed project. It writes the same managed-block `AGENTS.md` and one-line `CLAUDE.md` bridge that `protean dx install` writes, at the same pack version, and records them in `.protean/dx-state.json`. So `protean dx install`, `refresh`, and `check` all work on a fresh project with no manual setup step. The scaffold's `AGENTS.md` used to be the bare diagnostics-derived hard rules (byte-identical to `protean docs generate --type=agents`); it is now the richer form that composes the packaged pack guidance with those rules. `protean new` writes only this universal baseline; `.mcp.json` and the per-editor files (Cursor, Copilot, opencode) stay `protean dx install` choices.

`protean dx check` now verifies a required baseline plus whatever else is installed. `AGENTS.md` and the `CLAUDE.md` bridge are the required baseline and are always verified. `.mcp.json` and the per-editor files are optional: `check` verifies one only once it is present on disk or recorded in `.protean/dx-state.json`. A freshly scaffolded project carries only the baseline, so it passes. A project missing the baseline still fails. An editor file you never chose is no longer counted as drift. `protean dx diff` is unchanged: it always previews every managed target, the baseline plus every optional one.

`protean dx refresh` now writes only what a project already has: the required baseline plus every optional target present on disk or recorded in `.protean/dx-state.json`. It used to write all six targets, like `install`, so refreshing a scaffolded project after an upgrade created `.mcp.json` and every editor file. `install` is unchanged and stays the verb that opts a project into those files. `refresh` and `check` now share one scope, so `refresh` fixes exactly what `check` reports. Both verbs report an unreadable `.protean/dx-state.json` as the exit-2 environment error the docs describe for a state file that cannot be read. It used to read as an absent file, so every optional target counted as never installed.
