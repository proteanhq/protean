`protean new` now ships a dx-managed project. It writes the same managed-block `AGENTS.md` and one-line `CLAUDE.md` bridge that `protean dx install` writes, at the same pack version, and records them in `.protean/dx-state.json`, so a fresh project is managed by `protean dx` from birth: `install` adopts it, `refresh` updates it, and `check` reports it clean with no manual step. The scaffold's `AGENTS.md` used to be the bare diagnostics-derived hard rules (byte-identical to `protean docs generate --type=agents`); it is now the richer form that composes the packaged pack guidance with those rules. `protean new` writes only this universal baseline; `.mcp.json` and the per-editor files (Cursor, Copilot, opencode) stay `protean dx install` choices.

`protean dx check` now verifies a required baseline plus whatever else is installed. `AGENTS.md` and the `CLAUDE.md` bridge are the required baseline and are always verified; `.mcp.json` and the per-editor files are optional and are verified only once one is present on disk or recorded in `.protean/dx-state.json`. A freshly scaffolded project, which carries only the baseline, passes; a project missing the baseline still fails; and an editor file you never chose is no longer counted as drift. `protean dx diff` is unchanged: it always previews all six files.
