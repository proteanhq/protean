`@domain.application_service` now accepts constructor arguments, so a service can be built with fakes in a unit test. Defining `__init__` used to fail with `TypeError: object.__new__() takes exactly one argument`, which named neither the class nor `__init__` and read as a rule rather than the bug it was. A `@use_case` method called without an active domain context now raises a `ConfigurationError` naming the use case, instead of `AttributeError: 'NoneType' object has no attribute 'providers'` from inside the transaction machinery.

**Breaking (error type).** A `@use_case` called with no active domain context raised `AttributeError`; it now raises `ConfigurationError`. Code catching the old type stops catching it. The new error is deliberate rather than incidental, so it is worth catching by name if you rely on it.

**Migration:** [Application services accept constructor arguments](https://docs.proteanhq.com/reference/migration/v0-17/#application-services-accept-constructor-arguments)
