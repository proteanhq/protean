**Breaking.** Event-store subscriptions now report their exhausted positions as `dlq_depth` in `protean subscriptions status`, `/readyz`, the observatory and the `protean_subscription_dlq_depth` gauge. The count is the number of positions whose latest record in the subscription's `failed-*` stream is `Exhausted`, the same positions `protean eventstore dlq list` shows; it used to be `0`, so an alert on `dlq_depth > 0` can start to fire. The observatory's DLQ tab does not list these positions; clear them with `protean eventstore dlq replay` or `purge`. `protean eventstore dlq inspect` no longer shows a position that was replayed or purged after it was exhausted.

**Migration:** [Event-store subscriptions report their exhausted positions as DLQ depth](https://docs.proteanhq.com/reference/migration/v0-18/#event-store-subscriptions-report-their-exhausted-positions-as-dlq-depth)
