Fixed async command handling reporting a succeeded command as failed. The engine emitted a process-manager trace with an unguarded `issubclass` check that raised on a command stream's `CommandDispatcher` instance; the error was swallowed and turned a committed command into a failed result, so command positions were recorded as failed, retried, and could exhaust. The check now guards against a handler that is not a class.

Fixed `Engine` leaking the event loop it opens when construction then fails while wiring subscriptions, outbox processors or the DLQ task. The caller never gets a reference to the half-built engine, so nothing could close that loop; `Engine.__init__` now closes it before the error propagates.

Fixed `protean eventstore dlq inspect` showing an unrelated event when the message an exhausted position names is no longer in the store. Store reads are inclusive, so the read came back with the next message in the stream. `inspect` and `replay` now check the message they get back against the record's global position and treat a mismatch as unreadable, so a replay cannot dispatch the wrong message and mark the requested position resolved. Checking the per-stream ordinal is not enough: a restore that drops a stream's tail lets a later append reuse the dropped ordinal.

Fixed DLQ discovery skipping process managers. A non-partitioned process manager is wired as an event-store subscription and writes its own `failed-*` stream, but `discover_subscriptions` walked only event handlers, command handlers and projectors. Its exhausted positions were invisible to `protean eventstore dlq` (`list`, `inspect`, `replay` and `purge` all reported no such position) and its DLQ stream was never trimmed by DLQ maintenance nor reported by the observatory. A partitioned process manager stays out: the engine gives it one broker-backed subscription across its categories, which writes no failed-positions stream.
