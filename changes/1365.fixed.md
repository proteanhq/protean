Fixed async command handling reporting a succeeded command as failed. The engine emitted a process-manager trace with an unguarded `issubclass` check that raised on a command stream's `CommandDispatcher` instance; the error was swallowed and turned a committed command into a failed result, so command positions were recorded as failed, retried, and could exhaust. The check now guards against a handler that is not a class.

Fixed `Engine` leaking the event loop it opens when construction then fails while wiring subscriptions, outbox processors or the DLQ task. The caller never gets a reference to the half-built engine, so nothing could close that loop; `Engine.__init__` now closes it before the error propagates.

Fixed `protean eventstore dlq inspect` showing an unrelated event when the message an exhausted position names is no longer in the store. Store reads are inclusive, so the read came back with the next message in the stream. `inspect` and `replay` now check the message they get back against the position they asked for and treat a mismatch as unreadable, so a replay cannot dispatch the wrong message and mark the requested position resolved.
