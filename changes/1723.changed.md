**Breaking.** The IR now records a `Decimal` field as `"type": "Decimal"`, with `precision` and `scale` when the field sets them. It used to record `String` and drop both. The IR schema version moved to `0.3.0` to add the type (Protean 0.17 wrote `0.1.0`), so a committed `.protean/ir.json` baseline reports a version mismatch until you regenerate it. A baseline that holds a `Decimal` field also shows a breaking `String` to `Decimal` `field_type_changed` until the regenerated baseline is committed, and the `protean-check-compat` hook fails on that commit too, because it reads the baseline from `HEAD`. The generated contracts for a `Decimal` field change: JSON Schema emits a string with a decimal pattern plus `x-precision` and `x-scale`, Avro emits `bytes` with the `decimal` logical type when `precision` is set, and Protobuf stays `string`. `protean ir diff` adds a safe `field_precision_widened` change for a `Decimal` field whose precision is raised or removed with the same scale; lowering or adding precision, or changing scale, is a breaking `field_type_changed`.

**Migration:** [The IR schema is now v0.3.0](https://docs.proteanhq.com/reference/migration/v0-18/#the-ir-schema-is-now-v030)
