**Breaking.** Registering a standard repository for an event-sourced aggregate raises `IncorrectUsageError` with the code `USAGE_REPOSITORY_ON_EVENT_SOURCED_AGGREGATE`. It raises at registration when `part_of` is a class, and at `domain.init()` when `part_of` is a string. Before, the registration was accepted and the repository was never used, so a call to a custom method raised `AttributeError`. `domain.repository_for()` now returns the `BaseEventSourcedRepository` subclass registered for an event-sourced aggregate, the last one registered when there are several, and generates one only when none is registered. Before, it always generated one and ignored the registered subclass.

**Migration:** [A standard repository on an event-sourced aggregate raises](https://docs.proteanhq.com/reference/migration/v0-19/#a-standard-repository-on-an-event-sourced-aggregate-raises)
