`protean db migrate -m "<message>"` writes a migration for the differences between the domain's tables and the provider's database, and prints `No changes detected; no migration written.` when there are none. `protean db upgrade [revision]` applies migrations, up to `head` by default, and `protean db downgrade <revision>` reverts them, for example `-1` for the last one. With `--sql`, both print the SQL and do not connect to the database, and a plain `alembic ... --sql` run does not connect either. The commands work on SQLite, PostgreSQL (including a custom `schema`), MySQL, MariaDB and SQL Server. A migration leaves alone the tables the domain does not declare, alters SQLite columns by copying the table, and includes the provider's `Index.from_sql` indexes. The `SchemaMigrator` protocol gains `migrate`, `upgrade` and `downgrade` (#2135)
