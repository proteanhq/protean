`retention_maxlen` now works under `[server.stream_subscription]`. It was listed in that section's options table in the reference docs but the resolver never read it there, so setting it was silently ignored and no stream was trimmed.

**Breaking (a dormant setting goes live).** If your `domain.toml` already sets `retention_maxlen` under `[server.stream_subscription]`, it did nothing on 0.16 and takes effect on 0.17. Trimming can drop messages a slow consumer has not read yet, so a value chosen when it was inert is now a real retention bound. Check it before upgrading, or remove it to keep the previous behaviour.

**Migration:** [Streams are trimmed by default, and trimming can drop unread messages](https://docs.proteanhq.com/reference/migration/v0-17/#streams-are-trimmed-by-default-and-trimming-can-drop-unread-messages)
