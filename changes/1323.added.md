Added `protean verify`, a single command that runs a project's three health steps in order and returns one verdict: it initializes the domain (`Domain.init`), runs the domain check (`Domain.check`, the engine behind `protean check`), then runs the project's own `pytest` suite. It emits a compact per-stage table, or a machine-readable envelope with `--json`, and has a stable exit-code contract: `0` all green, `1` verify's own usage error (domain not found, or `--path` is not a directory), `2` domain failed to initialize, `3` check failed, `4` tests failed. The check stage honours `[lint].level` (default `"warn"`) — the same severity floor `protean check` uses — and validates the `[lint]` config the way `check` does, so a malformed `[lint]` block fails the check instead of reading as a false green.
