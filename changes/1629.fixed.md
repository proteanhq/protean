Top-level `[lint]` and `[observatory]` tables now load. The config loader kept only the sections listed in its defaults, and `lint` and `observatory` were not among them, so these tables were silently dropped from `domain.toml`, from `[tool.protean]` in `pyproject.toml`, and from a `Domain(config=...)` dict. Only an environment overlay such as `[test.lint]` reached the domain. Both sections now default to an empty table and load from every source.

**Breaking.** `[lint]` settings (`level`, `suppressions`, `rules` and the rest) now apply, so `protean check` can start failing on a project that used to pass. A malformed `[lint]` value that used to be ignored now fails `protean check` and `protean verify`. Building the IR fails on the same values, except a bad `level`, which the IR builder does not read. `Domain.check()` and the MCP `check` and `validate` tools now raise on these values instead of reporting a pass. `[lint]` also changes the IR diagnostics, so a committed IR can show as stale. `[observatory] trace_retention_days` now applies too. A `trace_retention_days` that reaches back before 1970 (such as `36500`) no longer stops trace persistence. The Redis trim point is now clamped at 0.

**Migration:** [The lint and observatory tables now load](https://docs.proteanhq.com/reference/migration/v0-18/#lint-and-observatory-tables-now-load)
