**Breaking, custom database adapters.** `BaseDAO` is split in two. An adapter's DAO class implements the `DAOPort` protocol, whose operations `filter`, `count`, `insert`, `update`, `update_all`, `delete` and `delete_all` take the session as their first argument and leave it open. Its `has_table` takes no session. Protean wraps it in a `DAO` service from `protean.infra.dao`, which runs the save lifecycle and the capability checks, and commits or rolls back each standalone operation through the provider's new `new_session()`, `commit(session)` and `rollback(session)`. The service's `update_all` takes the values as one mapping. A `save_if_absent` override becomes `InsertIfAbsentPort` with the `INSERT_IF_ABSENT` flag. A provider that declares a flag whose port its DAO class does not subclass now raises `ConfigurationError` on the first use of a repository, not on the first claim or delete. Code that used repositories and `QuerySet` needs no change.
