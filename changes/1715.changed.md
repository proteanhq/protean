**Breaking.** More internal paths that caught every exception now catch only the errors they expect, and any other error reaches the caller or the next handler up. The Redis brokers' `ping()` and connection checks handle only Redis and socket errors. Their `health_stats()` counts, and the Redis Streams broker's stale-consumer cleanup, handle only Redis errors. A broker's `ping()` and `health_stats()` still catch any other error: `ping()` returns `False`, and `health_stats()` puts the error text in its `details`. Other narrowed paths include traceparent parsing, the `server.transient_retry` settings, the command-deadline check in the retry loop, the caller-path guess in `Domain()`, source parsing for `protean check`, and the SQLAlchemy URI redaction in the connection-failure log. The paths that must keep a catch-all, such as the observatory scrapes, the subscription read loops and plugin loading, now name the reason in a comment. Several of them now log the error they used to drop: a custom lint rule that fails to import or raises, a failed trace-subscriber check, a stream whose length or lag cannot be read, an unreadable event store or cache in the observatory, and an unhandled endpoint error in the FastAPI middleware when the HTTP access log is off for that path. An invalid `server.transient_retry` setting now logs a warning when it falls back to the defaults. A Redis error during the stale-consumer cleanup at subscription startup now logs a warning, where it used to log at debug level. Ruff's `BLE001` rule now checks all of `src/` and `specs/`, so a new catch-all needs a `noqa` comment that gives its reason.
