**Breaking.** Internal paths that caught every exception now catch only the errors they expect. Any other error reaches the caller or the next handler up.

- The Redis brokers' `ping()` and connection checks handle only Redis errors, socket errors and a malformed server reply. Their `health_stats()` counts handle only Redis errors. A broker's `ping()` and `health_stats()` still catch any other error: `ping()` returns `False`, and `health_stats()` puts the error text in its `details`.
- The Redis Streams broker's stale-consumer cleanup, and its `info()` per consumer group, handle only Redis errors and names that are not valid UTF-8. The Redis PubSub broker's reconnect handles only a URI that cannot be parsed.
- Other narrowed paths: traceparent parsing, the `server.transient_retry` settings, the command-deadline check in the retry loop, the caller-path guess in `Domain()`, source parsing for `protean check`, and the SQLAlchemy URI redaction in the connection-failure log.
- The paths that keep a catch-all, such as the observatory scrapes, the subscription read loops and plugin loading, name the reason in a comment.
- Several catch-alls log the error they used to drop: a failed trace-subscriber check, a stream whose length, lag, consumers or DLQ depth cannot be read, an unreadable event store or cache in the observatory, a failed final send when the observatory shuts down, a health reply that cannot be sent, an exception whose `__str__` fails, and a failure while noting or logging discarded handler failures.
- The FastAPI middleware logs an unhandled endpoint error at error level when the HTTP access log is off for that path, or when the access log entry itself fails.
- A custom lint rule that fails to import or raises already logged a warning. The warning includes the exception text.
- An invalid `server.transient_retry` setting logs a warning when it falls back to the defaults. A Redis error during the stale-consumer cleanup at subscription startup logs a warning, where it used to log at debug level.
- The skill index in the dx pack logs at debug level when it cannot list the skills, where it used to return an empty index without a log.
- Ruff's `BLE001` rule checks `src/` and `specs/` without per-file exceptions, so a new catch-all that does not log the traceback or re-raise needs a `noqa` comment that gives its reason. The dx pack and the scaffold templates stay outside every ruff check, as before.
