The concepts pages now take their examples from `docs_src`, and tests run them. Running them showed several examples and claims that were wrong, and these are now corrected:

- The subscriber examples on the engine and subscriptions pages used `@handle(...)` on a method. A subscriber receives a payload through `__call__(payload)`, so the method never ran.
- The `Email` value object on the choosing-element-types page checked its address in `clean()`, which Protean never calls. It is now an `@invariant.post`. The value-object-with-identity example now uses `Auto(identifier=True)`, because a plain `Auto()` field does not raise.
- The always-valid page now creates its aggregates inside a domain context. Its `atomic_change` example now starts from an order where each change fails on its own, and its Layer 2 output shows the `max_length` error that `"FAKE"` actually raises.
- The stream-categories page now says commands go to `<stream_category>:command` streams, and that the engine creates one subscription per command stream category.
- The event-upcasting page said a string `event_type` raises `IncorrectUsageError`. A string that names a registered event is accepted, and one that names no registered event raises `ConfigurationError`. The page also now says an upcast event's `metadata.domain.version` holds the current version, not the stored one. The quoted framework code is updated to match the current source.
- The field-system page now shows the `min_length=1` and `max_length=255` constraints that Protean adds, and says a `max_length` set next to `choices` stays on the field.
- The event-sourcing page quotes the current rollback code in `raise_()` and the empty-list guard in `from_events`.
