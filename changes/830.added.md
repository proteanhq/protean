Added the publishing side of `sequential_by` per-key sequential processing (ADR-0028). Event handlers, command handlers, and process managers can now declare `sequential_by`: on event/command handlers it names a field on the payload; on a process manager it is a boolean that partitions each subscribed category by that category's `correlate` field. At registration the framework validates that every handled event/command carries the named field, that a stream category is partitioned by only one key, and that the target broker advertises `STREAM_PARTITIONING` (the single-threaded inline broker is the accepted no-op exception). The Unit of Work extracts the key off each event and validates it synchronously in the caller's transaction — a null, colon-bearing, reserved-lane/DLQ, or `__name__`-sentinel value fails the caller's operation and never enters the outbox — and stores it on a new `Outbox.partition_key` field. When the broker supports partitioning, the outbox processor routes such a row to `{stream_category}:{key}` (composing with the priority-lane suffix as `{stream_category}:{key}:{backfill_suffix}`) and abandons rather than retries a row whose key is somehow invalid. The consumer side (partition ownership lease, fencing, reclaim, discovery index) is deferred to #831.
