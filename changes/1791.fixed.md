A field declared with `choices` now gets the column type its choice values share on SQL databases, the same column a field of that Python type gets without `choices`. A `String` or `Status` with string choices keeps its `max_length` (`VARCHAR(n)`, where MySQL and MariaDB used to create `TEXT`), so it can be a unique or indexed column on SQL Server and MySQL. Integer, float, boolean, `Decimal`, `date` and `datetime` choices, including an `IntEnum` passed as choices, get their own column type instead of a string column, so an `Integer` with `choices` loads back as an `int`. The MySQL index-width check now counts these columns. Choices of mixed types, of one type with no column mapping, or an annotation that joins a `Literal` with another type keep the old column: `TEXT` on MySQL and MariaDB, `VARCHAR(max)` on SQL Server, and an unsized `VARCHAR` on PostgreSQL and SQLite.
