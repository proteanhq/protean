Cache adapters now declare their capabilities. `CacheCapabilities` in `protean.port.cache` has five flags: `KEY_VALUE` (reads, writes and deletes by key), `TTL` (per-key expiry), `PATTERN_MATCH` (glob reads, counts and deletes), `SHARED` (a second adapter built from the same config sees the first one's writes) and `DURABLE` (entries survive closing the adapter and building a new one). Two tiers group them: `LOCAL` is `KEY_VALUE | TTL | PATTERN_MATCH`, and `DISTRIBUTED` is `LOCAL | SHARED | DURABLE`. The memory cache declares `LOCAL` and the Redis cache declares `DISTRIBUTED`, through a new `capabilities` property. `capabilities` is abstract on `BaseCache`, a Provisional API, so a custom cache adapter must now define it; see the 0.18 migration guide.
