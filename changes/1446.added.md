Added `protean recover --reset-beyond-head`, which snaps each beyond-head checkpoint back to the stream head after a restore leaves it stale. It writes a fresh position to the `position-{fqn}-{category}` stream equal to the current stream head, reports what it changed, and exits `0`; a later `--verify-checkpoints` run then finds those subscriptions consistent. The flag needs `--verify-checkpoints` (that pass finds what to reset), and without it no run modifies any checkpoint. Under `--json` the envelope carries a `data.reset` list of the changes and a `data.summary.reset` count.
