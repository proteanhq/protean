**Breaking.** Fixed a silent lost update on the DAO `update()` / `QuerySet.update()` path: it bypassed the optimistic-concurrency version check, so two concurrent updates through it could both succeed and one was silently dropped. Updating an aggregate now advances its version and raises `ExpectedVersionError` on a stale write, matching `save()`. `update()` on a not-loaded entity (`state_.is_persisted` is `False`) now raises `ObjectNotFoundError` — previously such a call could blind-overwrite an existing row of that id with no version check. Load the aggregate before updating.

**Migration:** [`update()` now goes through the same path as `save()`](https://docs.proteanhq.com/reference/migration/v0-17/#update-now-goes-through-the-same-path-as-save)
