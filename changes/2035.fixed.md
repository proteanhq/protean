A failing after-commit callback no longer fails a commit whose writes are already durable. A command processed with `idempotency_key` inside an outer unit of work, whose handler returned a value `json.dumps` rejects (such as a `set` or a `datetime`), made the outer commit raise `TransactionError` and skip broker publishing and sync event dispatch. The unit of work now logs the callback's failure and finishes the commit. The idempotency store logs an unserializable result as a warning that names the key and does not record it, so a retry with the same key runs the command again. (#2035)
