A project that `protean new` creates on the `postgresql`, `sqlite` or `mssql` database now starts with the `migrations/` folder that `protean db init` writes, with no migration in it. Its `Makefile` has `db-migrate` (taking `m="message"`), `db-upgrade` and `db-check` targets, its README explains how to write the first migration, and its CI workflow runs `protean db upgrade` and then `protean db check` once `migrations/versions/` holds a migration. The placeholder `migrate` target is gone from the generated `Makefile` for every database. The `{{ package_name }}` placeholders that reached the generated `Makefile` unrendered (in `test-domain`, `docker-build` and other targets) now render to the package name. The generated `.gitignore` now ignores `*.db` files, so the SQLite database is not committed. The `--dry-run` list shows an empty folder with a trailing `/`, such as `migrations/versions/` (#2137)
