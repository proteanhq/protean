Fix the domain behavior guides so every example runs and shows real output. The eight pages (aggregate mutation, error handling, invariants, message enrichment, message tracing, raising events, status transitions and validations) now take their code from `docs_src`, and tests check the behaviour each page describes. The 30-day order date rule in the invariants example now checks the last 30 days, where it used to compare against 1 January 2020. The validations page shows the error messages Protean prints today. The event-sourced order on the raising events page sets its identity in its creation handler, so `from_events()` rebuilds it with the right id. The message tracing page says how `causation_id` differs between synchronous and asynchronous processing, and the invariants page says `exc.codes` lists each distinct code once.

An event rebuilt from a stored message, for example with `Message.to_domain_object()`, now keeps the `correlation_id` and `causation_id` it was stored with. A stored ID that is empty stays empty. Before, both came back as `None` outside a handler, and inside a handler they were replaced with the IDs of the message being handled.
