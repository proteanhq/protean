`protean outbox retry` and `protean outbox discard` no longer overwrite a newer failure on the same row. When a second operator retried the row and a worker's attempt then failed, the row came back to the status and retry count the first operator had read, so the first operator's stale discard or retry still went through. The write now also checks the row's version and advances it by one, so the stale command aborts with "Outbox row ... changed while the command ran" and writes nothing. On Elasticsearch, `update_all` and query filters now read and write a `_version` key in the `entity_version` field, where Elasticsearch stores the entity version.
