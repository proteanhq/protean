**Breaking.** `protean upgrade-check` now exits `1` when it finds warnings and `2` for a usage or environment error. Before, warnings exited `2`, the same code Click uses for an unknown option, so a script could not tell findings to review from a run that never happened. A bad `--format`, a malformed or misplaced `--pinned-version`, and a domain that does not load now exit `2` instead of `1`. A domain module that raises an error other than `ImportError` at import, an error while the domain initializes, and an error outside a single check now exit `2` where they used to end in a traceback. A check that fails on its own still reports `CHECK_FAILED` and exits `1`. Errors print on stderr and leave stdout empty, including under `--format json`. This breaks a script that reads `2` as "warnings found". The `--format json` output is still a plain list of findings.

**Migration:** [`upgrade-check` exits 1 for warnings and 2 for errors](https://docs.proteanhq.com/reference/migration/v0-19/#upgrade-check-exits-1-for-warnings-and-2-for-errors)
