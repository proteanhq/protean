`protean subscriptions status` no longer reports a Redis Streams subscription as caught up when Redis cannot report its lag. Redis 7 sends a nil `lag` for a consumer group created at an entry in the middle of a stream, or after an entry past the group's last-delivered id is deleted. `RedisBroker` read that nil as `0`, so the status showed `ok` with lag 0 while entries were still unread. The status now counts the entries after the group's last-delivered id with `XRANGE`, the fallback it already used on Redis before 7.0. When that count also fails, the lag is reported as unknown.
