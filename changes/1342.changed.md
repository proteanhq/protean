`protean add <element> <name>` now writes the slice to disk by default, where before it only previewed the plan. Pass `--dry-run` to keep the old preview-only behavior (`--apply` is the explicit form of the default, and the two flags cannot be combined). Apply is create-only: it refuses to overwrite an existing file, and if a write fails partway it rolls back what it wrote and names anything it could not remove. A conflict or a write failure exits `1`; `--dry-run --apply`, an unsupported element type, a bad name, or an unresolvable project still exit `2`. After a successful `add`, `protean verify` is green.
