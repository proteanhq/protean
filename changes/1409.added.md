A new pattern page, "Calling External Systems from Handlers", documents the handler transaction rule: a handler method persists or calls out, never both. It covers the split into a persisting method and a calling method, the event chain when the call needs a value the write produced, the idempotency-key answer when the two genuinely cannot be split, and the multi-facet fan-out recipe (fetch and persist the snapshot once, apply facets as sibling methods on one class, and why separate handler classes contend when they share an aggregate).
