`Cache.get_all` now paginates the same way on every adapter: matching keys are ordered ascending, `last_position` is a zero-based offset into that order, and `size` is a hard cap on the page. A negative `last_position` or `size` raises `ValueError` instead of silently slicing from the end. Redis previously forwarded `last_position` to `SCAN` as an opaque cursor and treated `size` as a work hint, so the same offset returned different entries than the memory cache, and a second Redis page was never reachable. Redis now scans all matching keys per call to produce the stable order. `Cache.count` on Redis now dedupes that scan too, so it no longer overcounts a key `SCAN` returns more than once and agrees with the number of distinct entries `get_all` returns.

**Migration:** [`get_all` paginates by a stable offset on every adapter](https://docs.proteanhq.com/reference/migration/v0-18/#get_all-paginates-by-a-stable-offset-on-every-adapter)
