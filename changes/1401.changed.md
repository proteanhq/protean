`Cache.get_all` now paginates the same way on every adapter: matching keys are ordered ascending, `last_position` is a zero-based offset into that order, and `size` is a hard cap on the page. Redis previously forwarded `last_position` to `SCAN` as an opaque cursor and treated `size` as a work hint, so the same offset returned different entries than the memory cache, and a second Redis page was never reachable. Redis now scans all matching keys per call to produce the stable order.

**Migration:** [`get_all` paginates by a stable offset on every adapter](https://docs.proteanhq.com/reference/migration/v0-18/#get_all-paginates-by-a-stable-offset-on-every-adapter)
