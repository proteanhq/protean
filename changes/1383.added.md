Trace validation for the transactional outbox: `make verify-specs` now records the real `OutboxProcessor` two-phase publish as it runs and replays the log against `specs/Outbox.tla` with TLC, so a recorded run of the shipped claim/publish/mark path is checked to conform to the model, not just that the model is sound. A fresh trace must also witness the window the protocol exists for: a crash after the broker publish but before the mark, so the message is reclaimed and published again (the at-least-once duplicate). Two negative checks keep a green run honest: a log that marks a row published with no preceding successful publish is rejected as a divergence, and a log with no redelivery is rejected as under-covered.
