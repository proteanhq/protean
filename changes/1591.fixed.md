Fixed three DX pack skill examples that declared a value object and then never used it. In the event-sourced-aggregate example `es_aggregate_with_entities.py`, `LineItem.unit_price` now holds the `Money` value object and the `ItemAdded` apply handler rebuilds it during replay, so the file demonstrates the value object its header advertises. Embedding `Money` also restored a rule the plain `Float` field had carried: `LineItem` now holds an invariant requiring a unit price of at least 0.01, and `add_item` no longer defaults that price to zero. The currency now lives on the `Order`: `OrderCreated` carries it, `ItemAdded` has no currency field at all, and the apply handler prices every replayed item in the order's currency. That is what makes `Order.total` safe to sum, and it returns `Money` instead of a bare float. An invariant on `Order` catches an order assembled by hand; during replay it stays quiet, because `from_events()` turns invariant checks off for the whole replay. In the add-field example `add_simple_field.py`, `Customer` now embeds its `ContactInfo` value object instead of repeating those fields as primitives. In the test-scaffold example `scaffold_aggregate_unit.py`, `LineItem.unit_price` now holds `Money` as well, and `add_item` wraps the plain number a caller passes, so the documented calls and the `order.total == 45.0` assertion on the skill pages still hold. `add_item` takes no currency argument, and `Order` carries an invariant for an order assembled by hand: `total` sums the item amounts, and `Money.add()` refuses to add across currencies, so an order holding both would contradict its own value object. Two committed test sweeps guard the pack from here on: every value object an asset declares must be referenced by that asset, and no pack page may name a `model` option on `@domain.aggregate` (the custom-model option is `database_model`). The value-object sweep reads references outside the declaring class only. It used to walk the whole module, so a value object carrying an operation over its own type looked used by its own body, which is how `scaffold_aggregate_unit.py` went unnoticed. `ItemAdded` now declares the same constraints as the `LineItem` it describes: the price minimum, a quantity of at least one, and the two string lengths. `raise_()` appends the event and then runs the apply handler, so a constraint living only on the entity was checked once the event was already pending, and a caller who caught the error and saved the order persisted a rejected event. `protean dx build-plugin` also skips `__pycache__` directories now, so bytecode left beside an asset by running it stays out of the committed plugin tree.
