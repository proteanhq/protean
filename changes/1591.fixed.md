Fixed two DX pack skill examples that declared a value object and then never used it. In the event-sourced-aggregate example `es_aggregate_with_entities.py`, `LineItem.unit_price` now holds the `Money` value object and the `ItemAdded` apply handler rebuilds it during replay, so the file demonstrates the value object its header advertises. Embedding `Money` also restored a rule the plain `Float` field had carried: `LineItem` now holds an invariant requiring a unit price of at least 0.01, and `add_item` no longer defaults that price to zero. `Order` gained a matching invariant, plus a guard in `add_item`, so every item on an order shares one currency, and `Order.total` returns `Money` instead of a bare float. In the add-field example `add_simple_field.py`, `Customer` now embeds its `ContactInfo` value object instead of repeating those fields as primitives. Two committed test sweeps guard the pack from here on: every value object an asset declares must be referenced by that asset, and no pack page may name a `model` option on `@domain.aggregate` (the custom-model option is `database_model`).
