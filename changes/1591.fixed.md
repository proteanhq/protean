Fixed three DX pack skill examples that declared a value object and then never used it. In the event-sourced-aggregate example `es_aggregate_with_entities.py`, `LineItem.unit_price` now holds the `Money` value object and the `ItemAdded` apply handler rebuilds it during replay, so the file demonstrates the value object its header advertises. Embedding `Money` also restored a rule the plain `Float` field had carried: `LineItem` now holds an invariant requiring a unit price of at least 0.01, and `add_item` no longer defaults that price to zero. The currency now lives on the `Order`: `OrderCreated` carries it, `ItemAdded` has no currency field at all, and the apply handler prices every replayed item in the order's currency. That is what makes `Order.total` safe to sum, and it returns `Money` instead of a bare float. `Order.total` refuses to total an order holding an item priced in some other currency, so a hand-assembled mixed order produces no number at all. An `@invariant.post` cannot carry that rule: `from_events()` turns post-invariants off for the whole replay, and outside replay `HasMany.add()` caches the item before it calls `_postcheck()` and does not undo the cache when the check raises, so a caller who catches the error still holds the item the rule rejected. In the add-field example `add_simple_field.py`, `Customer` now embeds its `ContactInfo` value object instead of repeating those fields as primitives. In the test-scaffold example `scaffold_aggregate_unit.py`, `LineItem.unit_price` now holds `Money` as well, and `add_item` wraps the plain number a caller passes, so the documented calls on the skill pages still hold. `add_item` takes no currency argument, so the documented path cannot mix currencies, and `total` folds the item prices with `Money.add()` instead of summing bare numbers, so an order assembled by hand cannot produce a total either. `total` returns `Money` now, and the `references/aggregate-tests.md` assertion reads `order.total.amount == 45.0`. `Order.create(items=...)` takes dicts in `add_item`'s shape now, as well as `LineItem`s already built. It passed whatever it was given straight to `add_line_items`, which wants entity instances, so a dict failed inside the framework with `'dict' object has no attribute '_set_root_and_owner'`. The event-sourced asset's factory already took dicts, so the two assets in the pack disagreed on what the same argument meant. `place()` and `cancel()` build their event before they change `status`. Both builds can fail: `total` refuses a mixed-currency order, and `OrderCancelled.reason` is required. Changing the status first left the order in the new state holding no event, and a retry was then rejected for being in that state already. Two committed test sweeps guard the pack from here on: every value object an asset declares must be referenced by that asset, and no pack page may name a `model` option on `@domain.aggregate` (the custom-model option is `database_model`). That second sweep reads the raw page and knows nothing about markdown. It used to decide first where on a page code could sit and read only there, and every version of that list was incomplete: a ```text block, an inline code span, a `~~~` fence, a four-space indented block. It now searches for the decorator's name and nothing else, and reads forward from each hit with the tokenizer, which decides whether a call follows. Neither the markup around a call nor what separates the name from its paren can hide it: `@domain.aggregate \` continued onto the next line is a call the older `aggregate\s*\(` pattern did not match. The half that looks for the option name in prose had the same blind spot from the other side: it cut every fence out of the page first, so a page naming the option inside a fence was checked by neither half. It reads the whole page now too. The value-object sweep reads references outside the declaring class only. It used to walk the whole module, so a value object carrying an operation over its own type looked used by its own body, which is how `scaffold_aggregate_unit.py` went unnoticed. `ItemAdded` now declares the same constraints as the `LineItem` it describes: the price minimum, a quantity of at least one, and the two string lengths. `raise_()` appends the event and then runs the apply handler, so a constraint living only on the entity was checked once the event was already pending, and a caller who caught the error and saved the order persisted a rejected event. `protean dx build-plugin` also skips bytecode now, by suffix and not only by `__pycache__` directory, so a `.pyc` left beside an asset stays out of the committed plugin tree whether it came from running the asset or from `compileall -b`.
