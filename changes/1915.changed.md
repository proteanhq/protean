**Breaking.** In a domain with sync command processing, `domain.process(command, asynchronous=True)` called inside an active Unit of Work (a handler, a `@use_case` method or a `with UnitOfWork():` block) now stores the command with the caller's writes and returns `None`. The command runs after the caller commits, in its own Unit of Work with its own version retry, so a version conflict on the command no longer re-runs a call the caller made before it. A failure reaches the caller's `commit()` as `TransactionError`. A command that Protean handles itself is now stored with `asynchronous` set to `False`, so the engine does not handle it a second time.

**Migration:** [`process(..., asynchronous=True)` inside a Unit of Work waits for the commit](https://docs.proteanhq.com/reference/migration/v0-19/#process-asynchronoustrue-inside-a-unit-of-work-waits-for-the-commit)
