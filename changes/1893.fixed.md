The outbox now claims rows of equal priority in the order they were written, so one aggregate's events go out in commit order. Before, `claim_batch` and `find_unprocessed` sorted by priority alone, so on PostgreSQL one aggregate's events could be published out of order. Rows are now ordered by priority, then `created_at`, then `sequence_number`, which the Unit of Work fills with each event's position in its commit. The `ix_outbox_active` index gains the `created_at` and `sequence_number` columns, so an existing database should rebuild it once.
