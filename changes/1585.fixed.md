**Breaking.** A `RawIndex` (from `Index.from_sql(dialect, ddl)`) that names a dialect the framework does not render index DDL for now raises `IncorrectUsageError` at `Domain.init()`, naming the element, the index, and the bad dialect. Before, an unknown dialect (a typo like `"postgres"` for `"postgresql"`, or a dialect with no provider) was accepted at registration and then silently dropped at every call site, so the aggregate looked indexed but never got the index on any dialect. The accepted set now lives in one core constant, `RENDERED_INDEX_DIALECTS`, and the SQLAlchemy adapter and the `protean schema render` CLI read it, so validation accepts exactly the dialects the renderer emits DDL for.

**Migration:** [A RawIndex with an unknown dialect now raises](https://docs.proteanhq.com/reference/migration/v0-18/#a-rawindex-with-an-unknown-dialect-now-raises)
