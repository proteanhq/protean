Claim and bounded delete are now chosen by provider capability flags. `BaseDAO._claim` runs the DAO's `claim` method when the provider declares `NATIVE_CLAIM`, a held-back claim reads its pages through `claim_candidates` when the provider declares `FILTERED_CLAIM_CANDIDATES`, and `BaseDAO._delete_top` runs `delete_top` when the provider declares `BOUNDED_DELETE`. Each method belongs to a port in `protean.port.dao` (`NativeClaimPort`, `ClaimCandidatesPort`, `BoundedDeletePort`) that the DAO class subclasses. A provider that declares a flag for a DAO class without its port raises `ConfigurationError`. Without the flag, `BaseDAO` runs the portable claim or delete inside the new `BaseDAO.claim_lock()`, which the memory adapter overrides with its provider lock. These replace the adapters' `_claim` and `_delete_top` overrides and the SQL adapter's dialect allow-lists. MySQL and MariaDB declare `FILTERED_CLAIM_CANDIDATES` only; PostgreSQL declares all three; SQLite and SQL Server declare `BOUNDED_DELETE` and `FILTERED_CLAIM_CANDIDATES`; memory and Elasticsearch declare `BOUNDED_DELETE`. A custom adapter that overrode `_claim` or `_delete_top` must move the override to the matching port method and declare the flag.
