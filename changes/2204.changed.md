**Breaking.** `Float` and `Integer` fields reject `True` and `False` with a `ValidationError` keyed on the field name, and so does a `List` of either for each element. Before, the fields stored `True` as `1.0` or `1`, so a flag passed to a numeric field by mistake was saved as a number with no error. Every other value the fields accepted is still accepted, including a string that holds a number. `Decimal` and `Boolean` fields are unchanged. Convert a flag with `int(flag)` or `float(flag)` before passing it, and correct stored events that hold `true` or `false` in such a field, or raise the event's version and register an upcaster that converts the value.

**Migration:** [`Float` and `Integer` fields reject a boolean](https://docs.proteanhq.com/reference/migration/v0-19/#float-and-integer-fields-reject-a-boolean)
