`EventStoreSubscription.replay_exhausted` now refuses a command whose deadline has passed before it dispatches it. It returns a `ReplayOutcome` (`RESOLVED`, `REOPENED` or `EXPIRED`) in place of a bool. On `EXPIRED` it writes no record, so the position stays exhausted for the operator to purge, and `protean eventstore dlq replay` shows its usual "deadline has passed ... Purge it instead" error. Before, calling the method directly, or a deadline running out between the CLI's last check and the dispatch, recorded the position `Resolved` although the handler never ran.

**Breaking (direct callers of `replay_exhausted`).** Every `ReplayOutcome` member is truthy, so code that tested the old bool result must compare against `ReplayOutcome.RESOLVED` instead.

**Migration:** [`replay_exhausted` returns a `ReplayOutcome` instead of a bool](https://docs.proteanhq.com/reference/migration/v0-18/#replay_exhausted-returns-a-replayoutcome-instead-of-a-bool).
