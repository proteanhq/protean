**Breaking.** The outbox now publishes a partition key's rows in commit order. For a category whose handler declares `sequential_by`, a row is claimed only when every earlier row of its key has been published or discarded, or is claimed in the same batch. Rows are grouped by target broker, stream category, partition key and priority lane. A failed row holds its key's later rows until its retry publishes, and an abandoned row halts the key until an operator retries or discards it. When a row fails mid-batch, the processor puts the later rows of its group from that batch back to pending without changing their retry counts. Other keys, other lanes and rows without a partition key keep flowing. Cleanup no longer deletes abandoned rows that have a partition key. Rows with no `stream_category`, such as rows written before the upgrade and not filled, are never held and hold nothing.

The outbox table gains a `stream_category` column and an `ix_outbox_hold_back` index. Protean does not change an existing table, so add the column before starting 0.19.
