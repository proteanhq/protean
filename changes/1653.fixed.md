Outbox reconciliation now rebuilds the external-broker rows of a `published` event. When a crash lost a published event's outbox rows, `protean outbox reconcile` and the server's startup sweep restored only the internal-broker row, so the event never reached the brokers in `[outbox].external_brokers`. Reconciliation now also creates one row per external broker, with the same `message_id` and `partition_key` the unit of work would have written. It reads the event class's current `published` flag and the current `external_brokers` list. An event counts as missing only when its internal row is missing, so external rows lost on their own are not rebuilt. Reconciliation also skips events older than the shorter of the two `[outbox.cleanup]` retentions. Cleanup deletes rows older than that, and before this change a restart after cleanup rebuilt those rows and sent the events again. The count that `reconcile_outbox` returns, and that the command prints, now includes the external rows. When nothing is repaired, the command now prints "Nothing to reconcile: no event in the scanned window is missing its outbox row."
