The outbox processor no longer holds a Unit of Work open across the broker-publish `await`. It now publishes to the broker first, then records the message's published/failed status in a short transaction. Holding a transaction across the publish let another coroutine on the async engine's event-loop thread share and corrupt the same thread-scoped SQLAlchemy session (which matters now that a UoW is a real database transaction). This also brings the framework's own code in line with the ADR-0027 guidance to do no external I/O inside a Unit of Work.
