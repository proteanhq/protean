Added `protean.dx`, an idempotent managed-file writer that the `protean dx` command stage will build on. It generates a rendered artifact into a user's project and can re-write it later without clobbering the user's own edits. Two merge modes cover the file shapes it ships. A managed-block merge handles co-owned text: the framework block sits between `PROTEAN:BEGIN`/`PROTEAN:END` marker comments, and only that block is replaced. A managed-JSON-keys merge handles files like `.mcp.json`: the rendered dict's top-level keys are set and every other key is preserved. A state file at `.protean/dx-state.json` records, per target, the pack version stamp and two content hashes. The managed-slice hash decides whether a re-apply is a create, a no-op, a safe update, or a conflict it refuses to write over. The whole-file hash flags when a user edited the file around an untouched block. A symlink target is refused rather than replaced, and an update writes a file back in the line ending it already uses. The create path reuses `scaffold/apply.py`'s atomic create-with-rollback, and the diff path mirrors the derive-and-compare shape of `scaffold/manifest.py` and mutates nothing. See ADR-0037.
