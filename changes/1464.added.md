Added `protean.dx`, an idempotent file-projection engine that the `protean dx` command stage will build on. It writes a rendered artifact into a user's project and can re-write it later without clobbering the user's own edits. Two merge modes cover the file shapes it ships: a managed-region merge for co-owned text files, where the framework block sits between `PROTEAN:BEGIN`/`PROTEAN:END` marker comments and only that block is replaced, and a structured-JSON merge for files like `.mcp.json`, where the rendered dict's top-level keys are set and every other key is preserved. A lockfile at `.protean/dx.lock` records, per target, the pack version stamp and two content hashes (the whole file and the managed slice), which lets the engine tell a user edit apart from a version change: a re-projection is a create, a no-op, a safe update, or a conflict it refuses to write over. The create path reuses `scaffold/apply.py`'s atomic create-with-rollback, and the diff path mirrors the derive-and-compare shape of `scaffold/manifest.py` and mutates nothing.
