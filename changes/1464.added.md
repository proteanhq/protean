Added `protean.dx`, an idempotent file-projection engine that the `protean dx` command stage will build on. It writes a rendered artifact into a user's project and can re-write it later without clobbering the user's own edits. Two merge modes cover the file shapes it ships. A managed-region merge handles co-owned text: the framework block sits between `PROTEAN:BEGIN`/`PROTEAN:END` marker comments, and only that block is replaced. A structured-JSON merge handles files like `.mcp.json`: the rendered dict's top-level keys are set and every other key is preserved. A lockfile at `.protean/dx.lock` records, per target, the pack version stamp and two content hashes. The managed-slice hash decides whether a re-projection is a create, a no-op, a safe update, or a conflict it refuses to write over. The whole-file hash flags when a user edited the file around an untouched region. A symlink target is refused rather than replaced, and an update writes a file back in the line ending it already uses. The create path reuses `scaffold/apply.py`'s atomic create-with-rollback, and the diff path mirrors the derive-and-compare shape of `scaffold/manifest.py` and mutates nothing. See ADR-0036.
