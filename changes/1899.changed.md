On SQL Server, the column Protean generates for a `DateTime` field is now `DATETIME2` instead of `DATETIME`. `DATETIME` rounds to about 3 milliseconds, so two timestamps written microseconds apart could read back equal, and the outbox could claim two commits' rows interleaved. `DATETIME2` keeps the microseconds Protean writes. `Date` fields and other databases are unchanged. Protean does not alter existing tables, so their columns stay `DATETIME` until converted.

**Migration:** [SQL Server stores `DateTime` as `DATETIME2`](https://docs.proteanhq.com/reference/migration/v0-19/#sql-server-stores-datetime-as-datetime2)
