Log records from child loggers such as `logging.getLogger("myapp.orders")` that reach the root logger's handlers now carry `correlation_id` and `causation_id` (and the trace ids when telemetry is on), and keys listed in `[logging].redact` are masked on them. Protean now attaches its logging filters to the root logger's handlers as well as to the root logger, because a logger's filters do not run for records that propagate from child loggers. This also holds in `protean server --workers N`: each worker's queue handler gets the filters, and the supervisor keeps the ids a worker set.
