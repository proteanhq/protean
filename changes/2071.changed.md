**Breaking.** A broker that declares `DEAD_LETTER_QUEUE` subclasses the new `DeadLetterQueuePort` and implements seven public methods: `dlq_list`, `dlq_get`, `dlq_replay`, `dlq_replay_all`, `dlq_purge`, `dlq_trim` and `dlq_depth`. `BaseBroker` no longer declares the `_dlq_*` hooks, and `domain.init()` raises `ConfigurationError` for a broker that declares the capability without the port. On a broker without the capability, the `Broker` service returns an empty result for each DLQ call. `dlq_inspect()` is now `dlq_get()`, which also changes the observatory's OpenAPI operation ID for `GET /dlq/{dlq_id}`. `dlq_trim()` takes a timezone-aware `older_than` in place of a stream ID, and the Redis broker now trims exactly. The inline broker keeps its DLQ as messages on `{stream}:dlq`, trims and counts it, and drops `get_dlq_messages()` and `reprocess_dlq_message()`. An inline entry's `dlq_id` is now its ID on the DLQ stream, and its `payload` includes `_dlq_metadata`.

**Migration:** [Dead letter queue operations move to `DeadLetterQueuePort`](https://docs.proteanhq.com/reference/migration/v0-19/#dead-letter-queue-operations-move-to-deadletterqueueport)
