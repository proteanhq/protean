Saving the same aggregate instance again without reloading it now writes a new
version each time, and the events raised between those saves get new ids
(`<stream>-1.1` and so on) instead of reusing the first save's id. Before, the
second save wrote the version the instance already had, so event handlers that
deduplicate by event id dropped the second event, and a stale copy loaded
before the second save could overwrite it without an `ExpectedVersionError`.
After a successful save, `_version` and `_next_version` on the instance now
match what a reload returns. Fact events keep the version of the save that
raised them.
