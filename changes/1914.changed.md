**Breaking.** A handler that runs while a Unit of Work is already active no longer retries a version conflict or a transient error in place. This covers a command processed synchronously from another handler or from a `@use_case`. Its Unit of Work joins the outer one, so the failed attempt had already marked the whole transaction for rollback: the retry then succeeded inside a transaction that was rolled back at commit, and the caller got a normal return with no error. The exception now propagates. The outermost `@handle` handler retries the whole chain in a fresh Unit of Work when its own retry policy covers the exception. A `@use_case`, a process manager or a caller-opened `UnitOfWork` has no retry, so its caller may now see `ExpectedVersionError` or the transient exception. A command processed synchronously with an `idempotency_key` inside an outer Unit of Work now records its key only when the outer transaction commits, so an outer retry runs the command again.
