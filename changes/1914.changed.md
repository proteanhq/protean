**Breaking.** A command or event handler that runs while a Unit of Work is already active no longer retries a version conflict or a transient error in place. This covers a command processed synchronously from another handler or from a `@use_case`. Its Unit of Work joins the outer one, so the failed attempt had already marked the whole transaction for rollback: the retry then succeeded inside a transaction that was discarded at commit, and the write was lost with no error. The exception now goes up. An enclosing handler retries the whole chain in a fresh Unit of Work, and a `@use_case` or a caller-opened `UnitOfWork` passes it to its caller, which may now see `ExpectedVersionError` or the transient exception where the write used to be lost.

**Migration:** [A nested handler's conflict reaches the enclosing handler or the caller](https://docs.proteanhq.com/reference/migration/v0-19/#a-nested-handlers-conflict-reaches-the-enclosing-handler-or-the-caller)
