Fixed building an aggregate, entity or projection from only some of a value object's flattened arguments. `Customer(billing_address_street="1 Main St")` failed when `Address` had another field that does not accept `None`, such as `city: str = ""`. Protean filled every missing argument with `None`. It now passes only the arguments you gave, and the value object's own defaults fill the rest. This also makes `Store(shipping_address_location=Location(...))` work when the nested value object is the only argument given. One case reads differently: a value object field that accepts `None` but defaults to something else, such as `city: str | None = "Unknown"`, now gets its default when you leave it out. It used to get `None`. Loading from a repository is unchanged, because every stored column is passed back in.
