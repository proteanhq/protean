The server, FastAPI and observability guides now take their code from tested examples, and the examples that did not run are corrected. The correlation guide's subscribers use `stream=` instead of `channel=`. The outbox guide's shell example reads abandoned rows through the provider's outbox repository with `domain._get_outbox_repo()`, an internal method, because `repository_for("Outbox")` fails; it passes `limit=None` so it lists every abandoned row. The tuning guide's `sequential_by` handler now handles an event, so its partition key takes effect. The priority lanes guide shows the `command_processing = "sync"` setting its example needs. The FastAPI, hardening and OpenTelemetry examples define the domain and app they use instead of importing them from `my_app` or `my_domain`. The HTTP wide events, hardening, logging and correlation guides note four known issues: an empty `correlation_id` on the HTTP wide event under Protean's own logging setup, per-handler DLQ overrides that have no effect, keyword arguments nested inside `event` in JSON log output, and an event rebuilt from a stored message that loses its correlation and causation IDs.
