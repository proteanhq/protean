On the PostgreSQL and MSSQL adapters, a Unit of Work now runs as one real database transaction instead of buffering writes under an AUTOCOMMIT engine (ADR-0027). Reads inside a UoW now see the UoW's own pending writes (read-your-writes) through `filter`, `count`, `exists`, and `get`, and in-UoW uniqueness validation sees them too. The UoW is now atomic for every aggregate shape: rolling back a UoW that added a child-bearing aggregate no longer leaves an orphaned parent, and a domain write commits atomically with its outbox message. The engine now runs at the default read-committed isolation, and a UoW holds a database connection for its duration, so keep units of work short and do no external I/O inside them.
