The `add-saga-flow`, `event-handler` (`$any` audit) and subscriber skill assets now keep one record when a message arrives twice. In both saga assets, `Inventory`, `Payment` and `Shipping` take the order id as their identity. A repeated `PlaceOrder` changes nothing. A repeated `CreateReservation`, `RequestPayment` or `CreateShipment` keeps the stored fields and raises the step's event again, and each start or intermediate saga handler returns when the saga's status is not the one its step expects. The two closing handlers return only when the saga already sits at their own end status, so an early `ShipmentDispatched` or `PaymentFailed` still ends the saga, and `on_payment_failed` releases the reservation by the order id. The `$any` audit entry takes the audited event's id as its identity, and the handler adds no entry for an event it has recorded. The `RegisterCustomer` and `OnboardEmployee` command handlers return when the record exists, so a repeated external message no longer raises `ValidationError`. The `add-saga-flow` step fragments, the `event-handler` quick example and the `$any` reference page show the same guards.
