The `add-saga-flow`, `event-handler` (`$any` audit) and subscriber skill assets now keep one record when a message arrives twice. In both saga assets, `Inventory`, `Payment` and `Shipping` take the order id as their identity. A repeated create command leaves the stored record as it is and raises the step's event again, and each saga handler returns when the saga has already passed its step. The `$any` audit entry takes the audited event's id as its identity, and the handler adds no entry for an event it has recorded. The `RegisterCustomer` and `OnboardEmployee` command handlers return when the record exists, so a repeated external message no longer raises `ValidationError`. The `add-saga-flow` step fragments, the `event-handler` quick example and the `$any` reference page show the same guards.
