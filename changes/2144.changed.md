**Breaking.** An idle event-store subscription now waits longer between reads instead of polling the event store in a tight loop. With the default `tick_interval` of 0, the wait starts at 10 ms after the first empty read; with a longer `tick_interval`, it doubles from `tick_interval`. Each further empty read doubles it again, up to the new `max_tick_interval` setting under `[server.event_store_subscription]` (default 1 second). A read that returns messages sets the wait back to `tick_interval`. The backoff adds up to 1 second before an idle handler sees a new event, and an idle server can take up to 1 second longer to shut down. When the domain sets no `max_tick_interval` and `tick_interval` is above 1, the wait stays at `tick_interval`. A `max_tick_interval` that is not a finite number of 0 or more is ignored with a `subscription.max_tick_interval_invalid` warning. Set `max_tick_interval = 0` to keep the old continuous polling. The outbox processor's existing backoff now uses the same helper, with no change in behaviour.

**Migration:** [Idle event-store subscriptions wait up to 1 second between reads](https://docs.proteanhq.com/reference/migration/v0-19/#idle-event-store-subscriptions-wait-up-to-1-second-between-reads)
