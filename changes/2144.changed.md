An idle event-store subscription now waits longer between reads instead of polling the event store in a tight loop. The wait starts at 10 ms after the first empty read, doubles on each further empty read up to the new `max_tick_interval` setting under `[server.event_store_subscription]` (default 1 second), and drops back to `tick_interval` when a read returns messages. A new event can take up to 1 second to reach an idle handler. Set `max_tick_interval = 0` to keep the old continuous polling. The outbox processor's existing backoff now uses the same helper, with no change in behaviour.
