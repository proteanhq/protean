**Breaking.** The `retention_maxlen` subscription option is removed, and a Redis stream is now trimmed by consumer progress. After each batch a subscription asks the broker to trim the stream it read, and the Redis broker removes only the entries every consumer group has read and acknowledged, with `XTRIM MINID`. A handler that had no profile or set `retention_maxlen` to `None` now has its stream trimmed. When some handler declares `sequential_by` on a category, every handler on that category reads per-key partition streams, and those streams are still not trimmed. A consumer group that was never read stops every trim of its stream until the group is deleted. A handler added later starts at the oldest entry left in the stream. A leftover `retention_maxlen` key in `[server.stream_subscription]`, `[server.subscriptions.<Handler>]` or a handler's `subscription_config` is ignored. A custom profile that sets it fails at startup with `ConfigurationError`, and passing it to `SubscriptionConfig` or `StreamSubscription` raises `TypeError`. `StreamRetentionPort.trim` takes only the stream name.

**Migration:** [`retention_maxlen` is removed](https://docs.proteanhq.com/reference/migration/v0-19/#retention_maxlen-is-removed)
