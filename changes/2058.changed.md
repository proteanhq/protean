**Breaking.** The event store's reads, writes, aggregate loading and snapshots moved from `BaseEventStore` into the `EventStore` service, which now lives in `protean.infra.event_store`; `protean.adapters.event_store` no longer defines it. `domain.event_store` is the service, and the adapter it builds is `domain.event_store._adapter`. The service has `append`, `read`, `read_all`, `read_last_message`, `category_head_position`, `load_aggregate`, `create_snapshot`, `create_snapshots` and `category`. The adapter methods of the same names call it, except `category_head_position`: the adapter has no method of that name, and its `stream_head_position` calls the service's `category_head_position`. `domain.event_store.store` returns the adapter as before. These adapter methods, apart from the static `category`, now act on the domain's adapter, `adapter.domain.event_store._adapter`: on an adapter built outside `domain.init()` they read and write the domain's event store, and before `domain.init()` they raise `ConfigurationError`. Causation tracing and `verify` stay on `BaseEventStore` and still read the adapter they are called on.

- `read(stream, position=0, limit=1000)`: the `no_of_messages` keyword is now `limit`, and the old keyword raises `TypeError`. The unused `sql` argument is gone.
- `category_head_position(category)` returns the `global_position` of the newest row in a category, or in the whole store for `$all`, and `-1` when there is none. For `$all` the row can be a snapshot row. A stream name such as `user-1` gives the newest row of that stream. `BaseEventStore.stream_head_position` calls it.
- `BaseEventStore._last_event_of_type` and `BaseEventStore._events_of_type` are removed.

**Migration:** [`BaseEventStore.read` takes `limit` and no longer takes `sql`](https://docs.proteanhq.com/reference/migration/v0-19/#baseeventstoreread-takes-limit-and-no-longer-takes-sql) and the two sections after it.
