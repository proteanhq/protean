**Breaking.** The event store's features moved from `BaseEventStore` into the `EventStore` service, which now lives in `protean.infra.event_store`; `protean.adapters.event_store` no longer defines it. `domain.event_store` is the service, and the adapter it builds is `domain.event_store._adapter`. The service has `append`, `read`, `read_all`, `read_last_message`, `category_head_position`, `load_aggregate`, `create_snapshot`, `create_snapshots` and `category`. The adapter methods of the same names call it, except `category_head_position`: the adapter has no method of that name, and its `stream_head_position` calls the service's `category_head_position`. `domain.event_store.store` returns the adapter as before.

- `read(stream, position=0, limit=1000)`: the `no_of_messages` keyword is now `limit`, and the old keyword raises `TypeError`. The unused `sql` argument is gone.
- `category_head_position(category)` returns the `global_position` of the newest message in a category, or in the whole store for `$all`, and `-1` when there is none. `BaseEventStore.stream_head_position` calls it.
- `BaseEventStore._last_event_of_type` and `BaseEventStore._events_of_type` are removed.

**Migration:** [`BaseEventStore.read` takes `limit` and no longer takes `sql`](https://docs.proteanhq.com/reference/migration/v0-19/#baseeventstoreread-takes-limit-and-no-longer-takes-sql) and the two sections after it.
