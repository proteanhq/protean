`protean upgrade-check --opportunities` reports the other direction from the readiness checks: shipped capability the domain still appears to hand-roll ("paying for capability you already own"). It ships three deterministic detectors, each reading the domain's source and each naming the release its capability arrived in: raw `sqlalchemy.text()` SQL sites the query API now covers (0.16.0), a custom ASGI middleware sitting beside `DomainContextMiddleware` (0.15.0), and a queue-like status field the outbox now covers (0.14.0). The pinned version resolves from the installed Protean by default and `--pinned-version` overrides it; a detector fires only when its capability's release is at or below the pin. Findings reuse the existing `UpgradeFinding` shape, `--format json`, and exit codes. Judgment-based capability advice stays out of OSS (the commercial Domain Assessment surface). (#1294)
