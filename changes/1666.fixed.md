The stdlib redaction filter now runs after Protean's correlation and trace-context filters on the root logger and each root handler. Listing `correlation_id`, `causation_id`, `trace_id` or `span_id` in `[logging].redact` now masks those attributes on the log record, so formatters and filters that read record attributes (a `%(correlation_id)s` format string, for example) see the mask. Protean's own JSON and console output already masked them. A `ProteanRedactionFilter` declared on the root logger in a `dict_config` is now also copied to each root handler, so it covers records from child loggers.
