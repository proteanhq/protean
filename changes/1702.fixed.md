Fixed the testing guide and the testing reference so their examples run. Each page now includes its examples from `docs_src`, and a test runs them under pytest.

- "Domain model tests" uses one consistent `Order`, `OrderItem` and `Inventory` across its examples. Before, the same classes took different fields in different examples.
- "Event sourcing tests" checks rejection messages by their full text. Its `test_create_order` example no longer takes an unused `test_domain` argument, and its `EventLog` example now runs.
- "Query shape tests" matches table names that SQLite quotes, such as `"order"`.
- The pytest plugin reference now says `test_domain` is function-scoped. Every test gets a fresh, initialized domain.
- The configuration examples in "Fixtures and patterns", "Integration tests" and the database setup pattern use provider names such as `"postgresql"`, `"sqlite"`, `"redis"` and `"message_db"`. Dotted class paths are rejected at startup.
- "Fixtures and patterns" lists `bdd` among the markers the plugin registers.
