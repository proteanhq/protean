Add a per-subscription circuit breaker to `StreamSubscription`. It counts consecutive handler-outcome failures and, once `circuit_breaker_threshold` (default 10) is reached, moves to OPEN and pauses reads for `circuit_breaker_reset_seconds` (default 60) so a struggling downstream stops receiving new batches. (The breaker gates reads only; messages already read in the tripping batch are still processed.) Pending messages stay in the stream for redelivery — the breaker never acks an unprocessed message. After the reset window it allows a single HALF_OPEN probe: a success closes the breaker, a failure re-opens it. Both keys resolve through the full subscription config hierarchy (server defaults, per-handler server config, handler `Meta`, profiles, `from_dict`/`from_profile`). Each transition records the `protean.subscription.circuit_breaker.state` counter and emits a `subscription.circuit_breaker.opened`/`closed`/`half_open` trace.
