`diff_ir()` now applies the compatibility report's field rules to published events. A field that keeps its name and changes its type, or changes its `Decimal` precision or scale in a breaking way, is listed in `contracts.breaking_changes` as `contract_field_type_changed`, and a required field added without a default is listed as the new `contract_required_field_added`. `summary.has_breaking_changes` follows, so a direct `diff_ir()` caller can now see a break it did not see before. The compatibility report fills `field_name` for `field_type_changed` and `required_field_added`, and `protean ir diff` prints once a break that both lists report. The `protean-check-compat` hook now prints contract breaks too. The exit codes of `protean ir diff` and the `protean-check-compat` hook do not change, except on a published event listed in `exclude`. On that event these changes now exit `1` and fail the hook under `strictness = "strict"`, and `protean ir diff` exits `0` instead of `2` under `strictness = "warn"`. An upcaster-covered version bump is not an exception, because the bump changes the event's type string and that was already a contract break.
