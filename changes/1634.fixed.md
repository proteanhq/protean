`DomainFixture.domain_context()` now resets the data of its own domain on exit. Before, it reset whichever domain was current at exit, so a test that left another domain's context pushed wiped that other domain and left the fixture's data in place. Such a test still fails with `AssertionError: Popped wrong domain context`, but the fixture now pops the leaked contexts and its own before raising. The fixture also pops its context when a reset raises. The `conftest.py` that `protean new` generates had the same fault: it now resets the project's own domain, and it clears brokers between tests too.
