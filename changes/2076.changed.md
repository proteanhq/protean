**Breaking.** Database providers implement `ProviderPort`, and a provider that runs native queries implements `RawQueryProviderPort`. The provider members are renamed: `is_alive()` is `ping()`, `_data_reset()` is `clear()`, `_create_database_artifacts()` is `create_schema()`, `_drop_database_artifacts()` is `drop_schema()`, `get_dao()` is `dao_for()`, `construct_database_model_class()` and `decorate_database_model_class()` merge into `model_for()`, `_raw()` is `raw()`, `__database__` is `database_type` and `conn_info` is `config`. `pool_stats()` is replaced by `health()`, which returns a `ProviderHealth` whose `pool` is `None` for a provider without a connection pool. `close()`, `create_schema()` and `drop_schema()` default to doing nothing. `provider.raw()` no longer checks `RAW_QUERIES`; `QuerySet.raw()` still does, through `DAO.raw()`. The Elasticsearch provider no longer replaces a JSON string in `database_uri` with the parsed dict in the domain configuration.

**Migration:** [A provider's `is_alive()` is now `ping()`](https://docs.proteanhq.com/reference/migration/v0-19/#a-providers-is_alive-is-now-ping) and the sections after it.
