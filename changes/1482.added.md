Added a Security Considerations reference page. It states Protean's security posture: field input validation is structural and not an injection boundary, `String` and `Text` fields do not sanitize by default (opt in with `sanitize=True` or `[field_defaults] sanitize`), the bundled adapters use bound query values while a provider's `raw()` path is the operator's boundary, secrets in configuration are supplied and protected by the operator, and transport security, authentication, rate limiting, and output escaping are left to the operator.
