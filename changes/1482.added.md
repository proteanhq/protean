Added a Security Considerations reference page stating Protean's security posture. Field validation is structural and not an injection boundary. `String` and `Text` fields do not sanitize by default; opt in per field with `sanitize=True` or domain-wide with `[field_defaults] sanitize`. The bundled adapters do not build queries by concatenating your field values into query text, and a provider's `raw()` path is the operator's boundary. Secrets in configuration are the operator's to supply and protect. Transport security, authentication, rate limiting, and output escaping are left to the operator, and the one network service Protean ships, the Observatory, is unauthenticated and binds loopback by default.
