Added a Security Considerations reference page stating Protean's security posture. Field validation is structural and not an injection boundary. `String` and `Text` fields do not sanitize by default; opt in per field with `sanitize=True` or domain-wide with `[field_defaults] sanitize`, and a field with `choices` is never sanitized. The bundled adapters do not build queries by concatenating your field values into query text, and a provider's `raw()` path is the operator's boundary. Secrets in configuration are the operator's to supply and protect. Transport security, authentication, rate limiting, and output escaping are left to the operator. Three network services ship, the engine health server (on by default, with a state-changing `POST /drainz`), the Observatory, and `protean mcp --http`; all three are unauthenticated and bind loopback by default.
