Added a Security Considerations reference page stating Protean's security posture. Field validation is structural and not an injection boundary. `String` and `Text` fields do not sanitize by default; opt in per field with `sanitize=True` or domain-wide with `[field_defaults] sanitize`, and a field with `choices` is never sanitized. The bundled adapters do not build queries by concatenating your field values into query text. Raw queries are the operator's boundary: the provider's `raw(query, data)` binds `data` on SQLAlchemy, while the repository path `QuerySet.raw(query, data)` ignores `data` and runs your string as is. Secrets in configuration are the operator's to supply and protect. Transport security, authentication, rate limiting, and output escaping are left to the operator. Four network services ship, the engine health server (on by default, with a state-changing `POST /drainz`), the Observatory, `protean mcp --http`, and the `protean docs preview` server. None of them authenticates the caller. The first three bind loopback by default; `protean docs preview` binds every interface (`0.0.0.0`) with no host option, so keep it on a trusted network or run `mkdocs serve --dev-addr=127.0.0.1:8000` yourself.
