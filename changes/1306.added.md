Documented the [broker partitioning contract](https://docs.proteanhq.com/reference/adapters/broker/partitioning/): the partition-discovery, fenced-ownership and stream-trimming methods an adapter implements to support `sequential_by`, and the `LeaseLostError` they raise. It was a public port surface with no documentation at all, so `sequential_by` was documented as a feature without its contract. Also fills gaps in the existing references: `[server.partitioning]` tunables and `[lint].check_adapter_calls` now appear in the configuration reference, `protean server` documents its `--acknowledge-event-store-risk` alias, `protean upgrade-check` lists its three new Unit-of-Work findings and warns that they widen exit code 2, and the custom-profile allowed-field list no longer omits the two circuit-breaker keys. The decorator reference had drifted from the code: twelve options were missing from it, including `suppress_checks` (accepted by every element), `sequential_by`, `idempotent`, `externally_populated`, the `retries`/`backoff`/`retry_exceptions` trio, `lenient`, `published`, and a command handler's `timeout`. All twelve are now listed, and a test reads `_default_options` off each element class so a new option fails the build the day it is added. `docs/api/testing.md` had the same problem from the other side: it named 3 of the 12 exports in `protean.testing.__all__`, so nine public test helpers, `drain` and `process_and_wait` among them, rendered nowhere. Also documented `domain.clock`, the seam for freezing time in tests, which was undocumented despite its own docstring advertising it, and noted that `ValidationError.messages` is not always a dict when domain code raises it.
