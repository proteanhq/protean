`protean dx install` now writes a `.mcp.json` that registers Protean's MCP server, so a coding agent can launch `protean mcp` without hand-editing the file. The merge is scoped to the `mcpServers.protean` key-path, so an existing `.mcp.json` keeps every other server you configured; `install` writes and reconciles only its own entry, and `dx check` flags a drifted or missing one. The registration key is `mcpServers`, which is what an MCP client reads; the MCP reference and the `.mcp.json` shipped in the Protean repository used to print `servers`, so a file copied from either was never discovered. Both now carry the same entry `dx install` writes. This adds a key-path JSON merge to the managed-file engine (ADR-0037): a `ManagedJsonKeys` request can now set its keys inside a nested object and preserve every sibling. (#1475)
