A stale write on an event-sourced aggregate with the outbox on raises `ExpectedVersionError` again, as it did in 0.16, so the handler-level version retry runs. Before, it failed with an outbox `IntegrityError` (on SQLAlchemy providers) or `ValidationError` (on the in-memory provider): the stale writer's outbox rows reuse the winner's message ids, and they reached the session before the event-store append could report the conflict. The unit of work now appends to the event store before it saves the outbox rows. An outbox save that fails for another reason now surfaces as `TransactionError`.
