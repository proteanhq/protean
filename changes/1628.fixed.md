A stale write on an event-sourced aggregate with the outbox on raises `ExpectedVersionError`, so the handler-level version retry runs. Before, it failed with an outbox `ValidationError` on the in-memory provider, and with an outbox `IntegrityError` on SQLAlchemy providers when the commit wrote two or more outbox rows. The stale writer's outbox rows reuse the winner's message ids, and they reached the session before the event-store append could report the conflict. The unit of work now appends to the event store before it saves the outbox rows. Aggregate enrichers and timestamp stamping still run on the outbox rows before the append, so a raising enricher fails the commit with nothing written. If an outbox save fails after the append, the commit raises `TransactionError` (a `ConfigurationError` propagates unchanged), and never `ExpectedVersionError`. With an external event store such as Message DB, the events are already durable at that point without their outbox rows, the same state a crash before the relational commit leaves.
