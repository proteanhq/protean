The engine runs outbox processors only for a managed database provider that at least one concrete aggregate is stored in. Before, it ran them for every managed provider, including the built-in `memory` provider and any provider that holds only projections, whose outboxes nothing writes to. `/readyz` `checks.subscriptions` and `protean subscriptions status` no longer list outbox rows for providers no aggregate uses. The response shape does not change. If a provider's outbox still holds unpublished rows when no aggregate uses it any more, the engine logs an `engine.outbox_rows_without_processor` warning at startup.
