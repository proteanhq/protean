Fixed an asynchronous event-store subscription dropping a failed message instead of retrying it. The read cursor was advanced before the failure was recorded to the recovery stream. Once that advance was durably checkpointed (checkpoints are batched, every `position_update_interval` messages), a crash would skip the message past both reprocessing and recovery; and if the recovery write itself failed, the already-advanced cursor skipped the message on the next read even without a crash. The failure is now recorded durably *before* the cursor advances, so a failed recovery write is retried and a crash leaves the message either re-read or recoverable. With recovery enabled (the default), recovery of a failed message is now crash-safe.
