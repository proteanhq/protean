### 10.1 Reference application and verified golden-path quickstart (#1480)

It shows the full write-then-read arc with the smallest domain a reader can hold in their head. The app loads the blog domain by file path and applies its own `domain.toml` in the app subfolder, so the config never leaks into the `python blog.py` quickstart. ### 10.2 Scaffold that runs, and `verify` to prove it (#1318)

#### Added

- `protean verify` runs a project's three health steps in order and returns one verdict: it initializes the domain (`Domain.init`), runs the domain check (`Domain.check`, the engine behind `protean check`), then runs the project's own `pytest` suite. It prints a compact per-stage table, or a machine-readable envelope with `--json`, and has a stable exit-code contract: `0` all green, `2` verify's own usage error (domain not found, or `--path` is not a directory), `3` the domain failed to initialize, `4` check failed, `5` tests failed. The check stage honours `[lint].level` (default `"warn"`), the same severity floor `protean check` uses, and validates the `[lint]` block the way `check` does, so a malformed `[lint]` block fails the check instead of reading as a false green. (#1323)
- An end-to-end acceptance test that runs `protean verify --json` on a freshly generated project and asserts a green verdict, with all three stages passing and at least one real test executed. (#1324)

#### Changed

- `protean new` now scaffolds a minimal walking skeleton instead of a broad demo. The example aggregate is trimmed to one slice that shows both paths end to end: `CreateExample` → `ExampleCreated` → an `ExampleProjector` that writes the `ExampleSummary` read model. The `activate`/`archive` transitions, the standalone event handler, the custom repository, and the unrelated `Address` value object are gone. The scaffold now also ships a smoke test plus two passing tests for that slice, and `pytest` (via `make test`) runs green on a fresh project. Previously a new project shipped no tests, so `pytest` collected nothing and exited 5 ("no tests ran") on first run. (#1321)
  The generated `tests/conftest.py` initialises the domain through a session-scoped autouse fixture instead of `pytest_sessionstart`, so a plain `pytest` / `make test` (driven by `testpaths`) sets up the domain context. The old hook only fired when the collection path passed through the package's test directory.

#### Removed

- The `logging.toml` file that `protean new` generated at the project root. Nothing in the framework read it; `[logging]` in `domain.toml` is the one config Protean loads (see `Domain.configure_logging`). (#1320)

#### Fixed

- Fix `protean new` so the generated example project initialises through a normal `domain.init()` and passes `protean check`. The scaffold previously shipped package re-exports that broke traversal, plus a projector and projection with a missing-module import, an aggregate referenced by name instead of class, and no identifier field. (#1316)
- Fix the scaffold's `.env.example`, `README.md`, and `docker-compose*.yml` to set `PROTEAN_LOG_LEVEL` instead of the unread `LOG_LEVEL`/`LOG_FORMAT`, so the documented env override actually takes effect. (#1320)

### 10.3 Diagnostic and result contracts (#1325)

#### Added

- Added `protean.ir.diagnostics`, one place that holds every `protean check` / IR diagnostic code and its metadata (category, level, one-line meaning, rationale, and fix), plus a typed `Diagnostic` wire shape and a `build_diagnostic` helper the producers build their records through. Diagnostic codes are now a stable public identifier: renaming or removing one is a breaking change, guarded by a golden code-set snapshot test, and a source scan fails the build if any code string is hard-coded outside the registry. The wire output (IR JSON, SARIF, and `check` results) is unchanged. (#1326)

#### Changed

- **Breaking (machine output and exit codes).** `protean check --format json` and `protean verify --json` now emit one shared, versioned result envelope (`{version, status, data, diagnostics}`) with a pinned JSON Schema, and both commands adopt one exit-code convention (`0` success, `1` a detected failure, `2` usage/environment error, `>=3` command-specific) that new commands can converge onto. `check`'s exit codes collapse (any findings failure is now `1`, not `1`-error-vs-`2`-warning; load/config errors move from `1` to `2`) and `verify`'s shift up by one (`2` usage, `3` init, `4` check, `5` tests). Machine output keeps stdout to the envelope alone, with errors and logs on stderr, even when a domain logs while it loads; and `check --format json` is never filtered by `--level` (that flag now only shapes the human view), so a `status="fail"` envelope always carries the diagnostics that caused it. Neither output had a stability guarantee before 1.0, so this is a direct correction rather than a deprecation-managed break. (#1329)
  **Migration:** [`check` and `verify` machine output changed shape and exit codes](https://docs.proteanhq.com/reference/migration/v0-18/#check-and-verify-machine-output-changed-shape-and-exit-codes)
- **Breaking (machine output).** `protean events catalog --json`, `protean subscriptions status --json`, and `protean projection status --json` now emit the shared CLI result envelope instead of a bare JSON array. The list moves under `data` (`data.events`, `data.subscriptions`, `data.projections`), and under `--json` stdout carries exactly one JSON object with logs on stderr. Usage and domain-load failures under `--json` are now the `status="error"` envelope on stdout and exit `2` (they printed a message and exited `1` before). (#1394)
  **Migration:** [`events catalog`, `subscriptions status`, and `projection status` JSON moved onto the envelope](https://docs.proteanhq.com/reference/migration/v0-18/#events-catalog-subscriptions-status-and-projection-status-json-moved-onto-the-envelope)

### 10.4 Diagnostic Contract (errors as steering) (#1330)

#### Added

- Init-time and runtime raises from the domain now carry a stable diagnostic `code`, plus a `location`, `rationale`, and `fix`, alongside their prose message. The codes live in the shared `protean.ir.diagnostics` registry, tagged `kind="raise"` to set them apart from the `protean check` lint rules, and the code survives a pickle round-trip so it is intact when an exception crosses the outbox or broker boundary. See the new [Init-time and Runtime Diagnostics](https://docs.proteanhq.com/reference/init-diagnostics/) reference for the full catalog. A few of these failures are statically detectable and could later grow a matching `protean check` rule under the same code. (#1331)
- Runtime invariant failures now carry a coded diagnostic. When an `@invariant.pre` or `@invariant.post` on an aggregate, entity, value object, or domain service fails, the raised `ValidationError` carries a stable `code` (and a `codes` list when several invariants fail together), plus the registry `rationale` and `fix`, so an agent or operator catching it gets an actionable steer. The errors dict is unchanged. Stamp your own code with `@invariant.pre(code=...)` / `@invariant.post(code=...)`. (#1332)
- Diagnostics can now name the command that fixes them. Where a deterministic command clears a failure, the diagnostic carries a `resolving_operation` (a structured `{command, args}` an agent runs directly, plus a rendered string for humans). The first pairing is the new `IR_STALE` code, produced by `staleness_diagnostic()` from a staleness result and resolved by `protean-check-staleness --fix`. A code whose failure no command resolves omits the field. (#1333)

### 10.5 Event Model renderer (#1334)

#### Added

- Added `protean docs generate --type=event-model`, an EventModeling slice-timeline view rendered from the IR. Each aggregate cluster becomes one left-to-right slice: its commands, the aggregate that holds state, the non-fact events it raises, and the downstream consumers of those events (projectors as read models drawn as cylinders, event handlers and process managers as automations drawn as hexagons, with a process manager's `start`/`end` lifecycle shown on its node and edge). `--format=mermaid` emits one combined `flowchart LR` timeline; `--format=markdown` emits one titled `mermaid` fence per slice. The whole render is derived from `to_ir()` alone, matching consumers to a slice's events by the event `__type__`, with no import of domain code and no dependence on the fail-open `method_edges`. The new type is its own view and is not folded into `--type=all`. (#1335)
- Added `UNRAISED_EVENT`, an info-level `protean check` fitness function that flags a domain event declared in a cluster that no aggregate or entity method raises. It is the producer-side mirror of `UNHANDLED_EVENT`: where that rule finds events nothing consumes, this one finds events nothing produces. An event counts as raised when a single method both calls `raise_` and constructs it, so the factory idiom `user.raise_(Registered(...))` is recognized. Published events stay in scope, since they are still produced inside the domain. The rule fails open: a cluster whose classes the index cannot reach emits nothing. (#1337)
- Added an annotation layer to `protean docs generate --type=event-model`. Human notes for the event model live in `.protean/annotations.toml`, a TOML file keyed by element FQN (`[annotations."myproj.example.aggregate.Order"]` with a required `note` string and an optional `owner`, per ADR-0032). On render, each note merges into every slice section that draws the element it keys: a note on an aggregate, command, event, or a consumer shows after that slice's Given-When-Then and before its diagram (a consumer drawn in two slices shows its note in both). A key that matches no drawn element (a fact event, or a note orphaned by a rename) is listed in an "Unmatched annotations" section at the end, so no note is dropped in silence. `--annotations <path>` overrides the default file; an explicit path that does not exist, or a malformed file, aborts the command before any output is written. With no annotations file present the render is unchanged. In `--format=mermaid` the flowchart body is untouched and only the unmatched report is appended, since notes are Markdown prose and cannot sit inside a raw flowchart. (#1338)
- Materialized `raises` and `invokes` edges into the IR under a new `method_edges` key on the element that owns each method, and bumped the IR schema to v0.2.0. `raises` (on aggregates and entities) lists the events a method raises, derived by co-location: it can over-report (an event built but not raised is still listed) and under-report (an event built in a helper and raised through it is missed). `invokes` (on command handlers, event handlers, projectors, and process managers) lists the element methods a handler method calls, matched by name against the methods in scope. The match is receiver-blind: it can miss a call (an ambiguous name is skipped) and it can record a wrong edge (a unique name is recorded even when the real receiver is something else). Projector and process-manager scopes are aggregate and entity method names, so those two rarely carry a real edge. Both edges are read from the source as written, so treat them as an approximate guide to the domain's behavior. `protean ir diff` reports a changed edge once under the owning element. (#1433)
- Added the `UNSOURCED_PROJECTION_FIELD` fitness function. It flags a projection field that no projector write fills, catching a dead read-model column that renders and carries a type but nothing ever populates. The check reads what projector methods write. A construction whose field set it cannot read disables it for the whole projection (a `**kwargs` splat, or a template mapping passed positionally), a projection with no observed write at all is skipped entirely, and the identity field is exempt. A `del` of a field, a write on one of an `@on` handler's own parameters (`self.field = ...`), a write on the receiver of any other projector method, and a write whose name is not a field of the projection do not count as filling a field. It works from observed writes, so it is advisory: when a projector writes some fields, a sibling field filled only through a path it cannot follow (a helper, a dict splat, a bulk `update(...)`) can still be flagged. (#1434)
- `protean ir diff --format=event-model` renders the diff in EventModeling slice vocabulary. An added command is a new slice, a removed projection is a removed read model, a projection that gained a field is a changed slice, over the same snapshot loaders and exit codes as the text format. (#1435)

#### Changed

- Each Markdown slice of `protean docs generate --type=event-model` now leads with a structural Given-When-Then before its diagram. Given is the aggregate, When lists the cluster's commands, and Then lists its non-fact events, all derived structurally from the IR. The `--format=mermaid` output is unchanged: GWT is a Markdown-only lead. (#1336)
- **Breaking.** The IR schema version moved from `0.1.0` to `0.2.0` to carry the new `method_edges` key. Schemas and documents validate both ways, and the `v0.1.0` schema stays published, but the checksum space changed: a committed `.protean/ir.json` baseline stamped `0.1.0` now makes `protean ir check` report a version mismatch and exit `3` (the `protean-check-staleness` hook prints the same message and fails) until you regenerate it. (#1433)
  **Migration:** [The IR schema is now v0.2.0](https://docs.proteanhq.com/reference/migration/v0-18/#the-ir-schema-is-now-v020)
- `--format` is now validated on `protean ir diff`, `ir show`, and `ir check`. An invalid value fails with a message listing the valid formats, where it used to fall through to the default format silently. (#1435)
  **Migration:** [`protean ir` rejects an unknown format value](https://docs.proteanhq.com/reference/migration/v0-18/#protean-ir-rejects-an-unknown-format-value)

### 10.6 Approach A: deterministic `add` (#1339)

#### Added

- Added a `protean.scaffold` package with a versioned `ChangePlan`: a serializable, previewable description of a change (create-file, edit-file, and structured config operations) that round-trips through JSON and renders a read-only preview without touching the filesystem. (#1327)
- Added a derived project manifest at `.protean/project.json`. `protean new` now writes it after generating a project, recording the package name, the domain name, and the ADR-0030 layout paths. Every field is recomputed from its own source on disk, so the file is derived and verifiable but never authoritative: `protean.scaffold.manifest.check_manifest_drift` recomputes the manifest and reports where a stored file disagrees with the code, changing nothing. See ADR-0034. (#1328)
- Add `protean add <element-type> <name>`, which computes a create-only ChangePlan for one aggregate slice and previews it without writing. (#1340)

#### Changed

- `protean add` now splits the aggregate it plans across a generation-gap seam: a generated base (`aggregate_base.py`, structure and wiring) and a hand-owned subclass (`aggregate.py`, your invariants and behavior). Each planned file records an `ownership` marker (`generated` or `hand_owned`) on the change plan, so once apply lands a re-run of `add` can refresh the generated base without touching the hand-owned subclass. `add` still only previews the plan today. (#1341)
- `protean add <element> <name>` now writes the slice to disk by default, where before it only previewed the plan. Pass `--dry-run` to keep the old preview-only behavior (`--apply` is the explicit form of the default, and the two flags cannot be combined). Apply is create-only: it refuses to overwrite an existing file, and if a write fails partway it rolls back what it wrote and names anything it could not remove. A conflict or a write failure exits `1`; `--dry-run --apply`, an unsupported element type, a bad name, or an unresolvable project still exit `2`. After a successful `add`, `protean verify` is green. (#1342)

### 10.9 Greenfield: text event-model to project scaffold (optional) (#1347)

#### Added

- Added `protean.scaffold.model_parser`, the textual event-model grammar of ADR-0041. `parse_model` reads a one-slice text model into a slice-shaped IR fragment (aggregate, command, event, and an optional projection and projector). The fragment reuses the IR's own field model, so there is one field vocabulary. The parse is deterministic, infers nothing, and reports every violation with its line number via `ModelParseError`. `emit_model` reads a full IR and a cluster FQN and writes grammar text back for the covered subset. On a cluster the grammar cannot express it raises `ModelEmitError`, so it never drops anything in silence: a field type or constraint outside the grammar, a shape it has no room for, or behaviour it carries no syntax for (a non-default element option, a declared invariant, a published event, a domain identity other than the default) is refused rather than emitted and quietly lost on the way back. A build-time conformance test round-trips a real `to_ir()` slice through emit and parse and matches the ADR worked example, so the grammar stays aligned with the renderer's vocabulary with no live sync. This is the parser half of `protean new --from-model` (#1347); the generator that promotes a fragment to a project is #1472. (#1471)
- Added a slice generator that promotes a slice-shaped IR fragment (ADR-0041) to the vertical-slice `ChangePlan` `protean add` writes: the aggregate, its command, event, command handler, projection, and projector. The fragment carries the element names, their fields (each an IR field entry), and the read-side wiring; the generator renders each field in its per-type declaration form and, when the read side is omitted, derives the default projection and projector from the event, so the slice still passes `protean verify`. `protean add` now routes through the generator by building a default fragment from the name. a field name the framework or the generated code already uses; an unsupported field type; an event whose `<slug>_id` cannot hold the aggregate's id, or that bounds it while the aggregate declares its own `id`, in which case the id comes from the caller and a longer one is rejected when the event is raised; an explicit projection not keyed on that field or carrying a field the event does not; an aggregate declaring the `<slug>_id` the event takes from its id; an aggregate declaring `id` in a shape that cannot reach the event's surfaced reference, which holds a string; a write side that does not line up, where the command's fields are not the aggregate's, the event carries a non-id field the aggregate does not declare, or a field the aggregate shares with the command or the event is declared in a different shape on each, since the generated code reads each of those off the other and copies the value across unchanged; an identity key marked outside a projection; a field whose required flag is not the one ADR-0041 gives it (every authored field is required, the projection's key is not); a field whose `kind` and `type` do not pair the way ADR-0041 pairs them, or a `max_length` that is not a positive integer or that sits on a type taking no bound; and a project whose composition root binds the domain to a name that slice's generated code uses. `SliceFragment` takes an optional `slug` so a caller that already normalized the aggregate name passes the slug it computed. `protean add` reports these as usage errors. `SliceFragment.from_mapping` reads the nested mapping the `protean new --from-model` parser returns, so a parsed model promotes through the same generator; it rejects a key it cannot read at every level of that mapping, down to the keys of a field entry, rather than dropping it or reading it as a name it is not and promoting a fragment that says something else. The parser derives the aggregate's slug from the normalized class name the fragment carries, which is the one the generator derives from it, so the surfaced `<slug>_id` the parser demands is the one the generator looks for. It rejects the few aggregate names where that slug differs from the one `protean add` derives from the name as authored (`aB` gives the class `AB`, whose slug is `ab`, where `add aB` gives `a_b`), so the same name writes the same slice whichever surface authored it. (#1472)

### 9.3 Durability & Disaster Recovery (#1352)

#### Added

- Added `read_all` on the event-store port: a generator that pages through a whole stream (`$all`, a category, or a specific stream) in bounded batches instead of relying on the `no_of_messages=1_000_000` sentinel that silently truncates past the read cap. Projection rebuilds now read every event through it, so a rebuild over a store larger than the old cap replays completely. (#1358)
- `verify()` on `BaseEventStore` and a new `protean eventstore verify` command run a read-only integrity check over the event store: every row is well-formed, per-stream positions are gapless, `global_position` is strictly increasing, message ids are unique, and no snapshot is malformed or runs ahead of its aggregate stream. A corrupt row is reported, not skipped. The command prints a table (or `--json` result envelope) and exits non-zero on any violation. (#1359)
- Added `protean recover --verify-checkpoints`, a read-only check for the window a backup restore leaves behind. When a checkpoint stream is backed up after the category stream it tracks, a restore can leave a subscription's checkpoint pointing past the head of the restored stream, so the subscription would skip every event in between. The command reports each event-store subscription whose checkpoint is strictly ahead of its stream head, prints a table (or `--json` result envelope), and exits `1` when any checkpoint is beyond head, `0` when all are consistent. A fresh subscription (checkpoint `-1`) and a caught-up one both read as consistent. Only event-store subscriptions track checkpoints, so broker and stream subscriptions are not examined. (#1361)
- Added `protean recover --reset-beyond-head`, which snaps each beyond-head checkpoint back to the stream head after a restore leaves it stale. It writes a fresh position to the `position-{fqn}-{category}` stream equal to the current stream head, reports what it changed, and exits `0`; a later `--verify-checkpoints` run then finds those subscriptions consistent. The flag needs `--verify-checkpoints` (that pass finds what to reset), and without it no run modifies any checkpoint. Under `--json` the envelope carries a `data.reset` list of the changes and a `data.summary.reset` count. (#1446)
- `protean recover --verify-checkpoints` now also flags recovery-tracking entries whose message a restore removed: an event-store subscription's recovery pass keeps a `recovery-checkpoint` snapshot and a `failed-positions` stream of positions to retry, and a restore can leave those naming a message the restored store no longer holds (it rolled the category stream back, or removed the specific aggregate stream a position points at). The recovery pass would re-read each, find nothing, and retry it forever. `--reset-beyond-head` clears those stale entries so the recovery pass stops chasing them. A restore that instead leaves the checkpoint watermark ahead of the failed-positions stream it references is reported as `unknown` (unverifiable): the failed stream reuses positions after such a truncation and cannot be reconstructed reliably, so the command reports the inconsistency and the reset leaves it untouched. (#1529)
  `protean subscriptions status --json` (and the Observatory subscription payload) now carry two more event-store fields alongside `position_stream`: `recovery_checkpoint_stream` and `failed_positions_stream` (both `null` for broker, stream, and outbox subscriptions).

#### Fixed

- Loading an event-sourced aggregate no longer fails when its snapshot predates the current schema. A snapshot that no longer matches the aggregate (a field renamed, removed, or newly required) is discarded, the aggregate is rebuilt from its event stream, and a warning is logged on the `protean.snapshot` channel so you know to rebuild snapshots. (#1362)
- `read("$all")` and `read_all("$all")` no longer raise `TypeError` when the store holds snapshots. Snapshot rows are written with no metadata, and deserializing them tripped over `None`; both readers now skip snapshot rows (type `SNAPSHOT`) and yield events and commands only. `read_all` pages on the raw store rows so an interleaved snapshot no longer truncates the read or desyncs the paging cursor. `read_last_message("$all")` also skips a trailing snapshot row and returns the newest event instead, so outbox reconciliation no longer crashes when a snapshot is the last row. (#1437)
- The in-memory event store's `_read_last_message` now does a true descending tail read. It read the first 1,000 rows and took the last of those, so once a stream passed 1,000 records it returned a stale record instead of the newest one. The append-only recovery-checkpoint stream reaches that size over many restarts, so an event-store subscription's recovery rebuild could resume from an old checkpoint and re-read failed positions it had already resolved. (#1529)

### 9.4 Runtime Operations (#1355)

#### Added

- Added a `protean eventstore dlq` command group to see the event-store dead-letter queue: `list` shows the positions a subscription exhausted (retried up to `max_retries` and gave up on), grouped by subscription, and `inspect <position>` re-reads the failing event. Both support `--json`. Exhausted records now also carry the failing event's `stream_name` and `stream_position` so `inspect` can locate the event; records written before this change fall back to the origin stream. (#1364)
- Added `protean eventstore dlq replay` and `protean eventstore dlq purge` to act on an exhausted event-store position. `replay` re-drives the failing event through its handler once (recording a resolution and exiting 0 on success, or reopening the position and exiting 1 on a repeat failure, which a running server retries after its next restart) without moving the subscription read cursor; `purge` appends a terminal `Purged` marker that clears the position and survives a rebuild. Replay confirms first, naming the target (an event handler, a projector, a process manager, or a command with or without an idempotency key) and warning that it re-runs handler side effects; it refuses a command whose deadline has passed, re-checked right before the dispatch so one that runs out while the prompt is open is refused too, and one whose handler is no longer registered (the dispatcher would route it nowhere and the replay would report it resolved without running anything). `EventStoreSubscription.replay_exhausted`, the method `replay` calls, returns a `ReplayOutcome` (`RESOLVED`, `REOPENED` or `EXPIRED`); it refuses a command whose deadline has passed before dispatch and returns `EXPIRED` without writing a record, so the position stays exhausted for a purge. The engine checks the deadline once more when it dispatches, so a deadline that passes between the two checks is still skipped and recorded `Resolved`. Both commands re-read the position's latest status right before they act, so a position another replay or purge cleared while the prompt was open is refused. Use `--handler` to pick one when a position is exhausted in more than one handler on the same stream. (#1365)
- Added a configurable graceful drain window and a `/drainz` endpoint on the engine health server. Set `server.drain_timeout` (seconds, default 10) in `domain.toml` to change how long shutdown waits for in-flight message handlers to finish before force-cancelling them. `POST /drainz` flips the engine to a new `draining` state distinct from `shutting_down`: the subscription poll loops stop pulling new batches while any batch already read finishes (no in-flight message is dropped), and the process stays alive so an orchestrator can quiesce it before sending SIGTERM. The outbox keeps flushing committed rows while draining, and partitioned subscriptions keep renewing their held leases so they are not abandoned mid-drain. While draining, `/readyz` reports not-ready (503) so a load balancer stops routing, while `/healthz` and `/livez` stay green. `/drainz` drains the worker that answered the request, so under `--workers N` an orchestrator must POST to every worker's health port; the response carries that worker's `pid`. `protean server --reload` sizes its worker-termination budget from `drain_timeout`, so a longer window is honoured there too. (#1366)
- Event-store subscriptions now report how far behind they are in seconds, not just in message count. `SubscriptionStatus` carries a new `lag_seconds` field: `0.0` when caught up, the wall-clock gap since the last processed position when lagging, and `None` when the seconds cannot be computed (no timestamp, an unparseable timestamp, or an unknown message-count lag). The seconds reach the same reporting surfaces as the message-count lag: the `Lag (s)` column and `--json` output of `protean subscriptions status`, the `/readyz` subscription details, the `protean.subscription.lag_seconds` OTel gauge (unit `s`), the `protean_subscription_lag_seconds` hand-rolled Prometheus fallback, and the Observatory `/handlers` and process-manager JSON APIs (aggregated as the worst per-stream staleness). A missing value is reported as unavailable, never as `0.0`, so it can never read as "caught up". (#1367)
- Added a `lag_drain_rate` to every per-subscription row in the `/readyz` `checks.subscriptions.details` block. It is the change in `lag_seconds` per second: negative while a backlog drains, positive while it grows. The health server's refresher keeps a bounded sliding window of the last 30 lag samples per subscription and fits a least-squares slope over them. It reads `null` until two refreshes have landed, and for any subscription whose `lag_seconds` is unknown. An unreadable lag also starts that subscription's window over, so the first refresh after it becomes readable again reads `null` rather than a slope stretched across the gap. It is not a `SubscriptionStatus` field and not a new metrics gauge: a metrics backend derives the same signal from the existing lag-seconds gauge. (#1368)

#### Fixed

- Fixed async command handling reporting a succeeded command as failed. The engine emitted a process-manager trace with an unguarded `issubclass` check that raised on a command stream's `CommandDispatcher` instance; the error was swallowed and turned a committed command into a failed result, so command positions were recorded as failed, retried, and could exhaust. The check now guards against a handler that is not a class. (#1365)
  Fixed `Engine` leaking the event loop it opens when construction then fails while wiring subscriptions, outbox processors or the DLQ task. The caller never gets a reference to the half-built engine, so nothing could close that loop; `Engine.__init__` now closes it before the error propagates.
  Fixed `protean eventstore dlq inspect` showing an unrelated event when the message an exhausted position names is no longer in the store. Store reads are inclusive, so the read came back with the next message in the stream. `inspect` and `replay` now check the message they get back against the record's global position and treat a mismatch as unreadable, so a replay cannot dispatch the wrong message and mark the requested position resolved. Checking the per-stream ordinal is not enough: a restore that drops a stream's tail lets a later append reuse the dropped ordinal.
  Fixed DLQ discovery skipping process managers. A non-partitioned process manager is wired as an event-store subscription and writes its own `failed-*` stream, but `discover_subscriptions` walked only event handlers, command handlers and projectors. Its exhausted positions were invisible to `protean eventstore dlq` (`list`, `inspect`, `replay` and `purge` all reported no such position) and its DLQ stream was never trimmed by DLQ maintenance nor reported by the observatory. A partitioned process manager stays out: the engine gives it one broker-backed subscription across its categories, which writes no failed-positions stream.

#### Changed

#### Added

- A query can now declare the type its handler returns by subscripting the base: `class GetOrderSummary(BaseQuery[OrderSummary])`. `domain.dispatch` then resolves to that type at the call site, so the result is typed instead of `Any`. This works under both mypy and pyright without the mypy plugin, because it is plain generics and typed overloads on `dispatch`. Declaring the result type is optional. A bare `BaseQuery` subclass and a decorator-only query both keep dispatching to `Any` and behave exactly as before, including under `mypy --strict`, because the type parameter defaults to `Any`. See ADR-0043. (#1118)
- Added `Custom`, a public field factory for a field over a custom Python type: `Custom(python_type, *, validators=(), serializers=(), **constraints)`. Pass the type plus the Pydantic validators (a `PlainValidator` parses a raw value into it, an `AfterValidator` checks it after) and serializers it needs, and it behaves like any built-in field: `required`, defaults, constraints, and `ResolvedField` reflection all work. Implement `to_dict()` on the type and it round-trips through save, reload, and event replay, because Protean's persistence and event payloads serialize through `ResolvedField.as_dict`; query filters serialize the same way, so `unique=True` and a filter carrying a live instance both work against a real database. `choices` is rejected at declaration, because a choice set would discard the custom type. The mypy plugin reads the type from the first argument, so `Custom(Color, required=True)` type-checks as `Color`. `Custom` ships Stable. A type that needs no Protean machinery still uses the raw `Annotated[YourType, Field(...)]` escape hatch. A reusable conformance check, `protean.integrations.pytest.custom_field_conformance.run_custom_field_conformance`, runs a `Custom` field against the whole contract (validation order, reflection, and the round-trip). - Added a Security Considerations reference page stating Protean's security posture. Field validation is structural and not an injection boundary. `String` and `Text` fields do not sanitize by default; opt in per field with `sanitize=True` or domain-wide with `[field_defaults] sanitize`, and a field with `choices` is never sanitized. The bundled adapters do not build queries by concatenating your field values into query text. Raw queries are the operator's boundary: the provider's `raw(query, data)` binds `data` on SQLAlchemy, while the repository path `QuerySet.raw(query, data)` ignores `data` and runs your string as is. Secrets in configuration are the operator's to supply and protect. Transport security, authentication, rate limiting, and output escaping are left to the operator. Four network services ship, the engine health server (on by default, with a state-changing `POST /drainz`), the Observatory, `protean mcp --http`, and the `protean docs preview` server. None of them authenticates the caller. The first three bind loopback by default; `protean docs preview` binds every interface (`0.0.0.0`) with no host option, so keep it on a trusted network or run `mkdocs serve --dev-addr=127.0.0.1:8000` yourself. (#1482)

It declares `RELATIONAL | NATIVE_JSON`: MySQL 8 has a real `JSON` column type, and no array type, so a `List` field is stored as JSON the way the MSSQL provider already does. The capability-gated conformance battery passes against MySQL 8.4 and MariaDB 11.4 with `native_array` the only deselection, and both servers run in the `protean test -c FULL` matrix. Four things are set up front because MySQL's defaults are wrong for Protean and fail silently: tables are created `CHARSET=utf8mb4` with an accent- and case-sensitive collation (`utf8mb4_0900_as_cs` on MySQL, `utf8mb4_uca1400_as_cs` on MariaDB, which is the only name MariaDB before 11.4.5 knows), because the server default ignores case and accents and would make `exact`, `contains`, `startswith` and `endswith` match rows they should not; every `DateTime` maps to `DATETIME(6)`, because a plain `DATETIME` drops microseconds on write with no error; the engine opens at `READ COMMITTED`, because InnoDB's `REPEATABLE READ` default breaks the ADR-0027 Unit of Work contract; and a `String` with no `max_length` becomes `TEXT`, because MySQL cannot create a `VARCHAR` without a length. A string column that is a primary key or `unique=True` raises `IncorrectUsageError` naming the field when it has no length or exceeds 768 characters, which is InnoDB's 3072-byte index key limit in `utf8mb4`. The outbox claim and the bounded delete take the portable path: MySQL has `SKIP LOCKED` but no `UPDATE ... RETURNING`, and rejects a subquery that reads the table being deleted from. `collation` is a provider config key, validated against the charset at `domain.init()`; the charset itself is pinned to `utf8mb4`, since a narrower one cannot hold the 4-byte characters Protean stores. See the [MySQL reference](https://docs.proteanhq.com/reference/adapters/database/mysql/). (#1580)

#### Fixed

- **Breaking.** `protean ir diff` now reports the changes that stop an event-sourced aggregate being rebuilt from its events. Turning event sourcing on or off, moving an aggregate's `stream_category`, pointing its identity at another field, and dropping an `@apply` handler while its event survives are each breaking on their own, whether or not the aggregate's fields moved. An event-sourced aggregate's authoritative state is a stream of events, so none of these is a field change and none was reported anywhere: a domain could move a stream category, strand every existing aggregate's history, and still pass the compatibility check clean. A domain that made one of these changes and passed before will now fail the check. (#841)

- **Breaking.** Reconcile the subscription and InlineBroker retry/DLQ layers so a subscription owns retry and dead-lettering end-to-end. For a stream consumed by a `BrokerSubscription` or a `StreamSubscription` (the default type), the InlineBroker now holds and redelivers a nacked message with no independent ceiling of its own: a persistent `{stream}:dlq` outage no longer routes the message to the broker's native DLQ, its stale-in-flight timeout sweep holds the message instead of dead-lettering it, and no `retry_counts` entry leaks. The subscription's `{stream}:dlq` is the single dead-letter destination for these streams, so `protean dlq list` no longer surfaces such a message out of the broker's native DLQ. The InlineBroker also caps its backoff delay so neither an unbounded owned-stream retry count nor a large configured `backoff_multiplier` can overflow the calculation and freeze a message, and a configured `retry_delay` of zero stays zero at every retry count. ## [0.16.2] - 2026-07-05

### Fixed

- Fix `datetime` values in serialized payloads being encoded with `str()` (a space-separated form) instead of ISO-8601. This only affected real JSON-backed stores (event store, Elasticsearch, outbox); the in-memory adapter was unaffected. Records written before the fix remain readable (`datetime.fromisoformat()` and Pydantic parse both forms). (#1039)
- Fix a `Date` (`datetime.date`) field on a command or event raising `TypeError: Object of type date is not JSON serializable` when the message is processed. `ResolvedField.as_dict` now serializes plain `date` values to ISO-8601 strings; previously only `datetime` had a branch, so a raw `date` reached the checksum's `json.dumps` and failed. (#1046)
- Fix `repository.add()` leaving an `Auto(increment=True)` identity as `None` for stores that assign the value during create (e.g. the in-memory provider). The generated value is now reflected back onto the aggregate instance after `add()`, restoring parity with `dao.create()`. (#1056)
- Fix a DB-assigned `Auto(increment=True)` identifier not being reflected back onto the aggregate when persisting through a relational adapter (SQLAlchemy → Postgres/SQLite/MSSQL). After `repository.add()` (or `dao.create()`) the generated primary key now populates the original instance, including when the persist runs inside an outer `UnitOfWork`, instead of staying `None` until commit. Because reflecting the value forces the insert to flush early, a constraint violation on such an insert may now surface at `add()`/`create()` time rather than only at commit. (#1059)
- Fix an embedded `ValueObject` whose fields hold default/falsy values (e.g. all zeros) being reconstructed as `None` after persist + reload. Presence was gated on truthiness — and such a VO is falsy — so it was reset to `None` on assignment and dropped from serialization. Presence is now decided by identity (`is not None`), so an explicitly-assigned VO round-trips to an equal VO across the in-memory, relational, and Message-DB adapters (and on event-sourced aggregates); an unset VO still reads back as `None`. Note: `bool(vo)` still reports an all-default VO as falsy (check presence with `agg.vo_field is not None`), and a VO whose every field is `None` still reads back as `None` from flattened storage. (#1078)
- Enforce `Index(unique=True)` declarations in the in-memory repository. A save or update that violates a single-column or composite unique index now raises `ValidationError` (the same error already raised for field-level `unique=True`), so memory-mode tests catch duplicate-key regressions instead of silently accepting them. NULLs are treated as distinct, matching PostgreSQL/SQLite semantics. (#1071)
- Make `Outbox.target_broker` NOT NULL so a NULL row can no longer bypass the `(message_id, target_broker)` unique index — the dual-write idempotency guard (NULLs compare as distinct in a unique index, silently reopening the duplicate-publish window). It now defaults to the internal broker name; the framework always sets it on write, and legacy rows with a NULL `target_broker` are coerced to the default broker name on read. (#1041)
- `protean upgrade-check` now diffs a live outbox table for the intra-0.16 structural migrations it previously missed: a nullable `target_broker` (emitting the backfill + `SET NOT NULL`) and a legacy `message_id`-only unique index (emitting the composite-index swap), alongside the existing VARCHAR-bounds check. The [v0.16 migration guide](docs/reference/migration/v0-16.md) gains the matching `target_broker` NOT NULL recipes. (#1093)
- Fix projectors rejecting the `retries`, `backoff`, and `retry_exceptions` options with `Unknown option(s)`. Projectors now accept them for per-projector transient-failure retry, mirroring event and command handlers. (#1076)
- Fix `protean check` raising a `PROJECTION_WITHOUT_PROJECTOR` false positive for projections populated by a subscriber or event handler (the anti-corruption-layer / cross-domain pattern) rather than a co-located `@projector`. Declare such projections with `@domain.projection(externally_populated=True)` to record that they are populated externally and suppress the warning. (#1013)

### Upgrade Notes

- **Outbox `target_broker` NOT NULL (#1041).** New deployments get a `NOT NULL target_broker` column automatically. Existing deployments keep their current (nullable) column — Protean does not auto-alter tables — and continue to read any legacy NULL rows safely. To enforce the constraint on an existing database, backfill and add it manually, e.g. `UPDATE outbox SET target_broker = 'default' WHERE target_broker IS NULL;` followed by an `ALTER TABLE ... ALTER COLUMN target_broker SET NOT NULL`.

- Support the Elasticsearch 8.x client (`elasticsearch` / `elasticsearch-dsl` 8.x), which fresh installs now resolve to by default. This also allows `urllib3` 2.x, resolving the related security advisory. **The 8.x client requires an Elasticsearch 8.x server.** Deployments still running an Elasticsearch 7.x server should pin `elasticsearch<8` to keep the 7.17 client, which connects to both 7.x and 8.x servers. To reach it from another host, pass `--host 0.0.0.0` (or another address) explicitly; binding a non-loopback address now logs a warning. Expose it only on a trusted network behind an authenticating reverse proxy. **Upgrade impact:** if you relied on the default being reachable remotely (e.g. a Docker port mapping), add `--host 0.0.0.0` to your `protean observatory` invocation.
