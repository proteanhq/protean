## [Unreleased]

### 10.2 Scaffold that runs, and `verify` to prove it (#1318)

#### Added

- `protean verify` runs a project's three health steps in order and returns one verdict: it initializes the domain (`Domain.init`), runs the domain check (`Domain.check`, the engine behind `protean check`), then runs the project's own `pytest` suite. It prints a compact per-stage table, or a machine-readable envelope with `--json`, and has a stable exit-code contract: `0` all green, `2` verify's own usage error (domain not found, or `--path` is not a directory), `3` the domain failed to initialize, `4` check failed, `5` tests failed. The check stage honours `[lint].level` (default `"warn"`), the same severity floor `protean check` uses, and validates the `[lint]` block the way `check` does, so a malformed `[lint]` block fails the check instead of reading as a false green. (#1323)
- An end-to-end acceptance test that runs `protean verify --json` on a freshly generated project and asserts a green verdict, with all three stages passing and at least one real test executed. (#1324)

#### Changed

- `protean new` now scaffolds a minimal walking skeleton instead of a broad demo. The example aggregate is trimmed to one slice that shows both paths end to end: `CreateExample` → `ExampleCreated` → an `ExampleProjector` that writes the `ExampleSummary` read model. The `activate`/`archive` transitions, the standalone event handler, the custom repository, and the unrelated `Address` value object are gone. The scaffold now also ships a smoke test plus two passing tests for that slice, and `pytest` (via `make test`) runs green on a fresh project. Previously a new project shipped no tests, so `pytest` collected nothing and exited 5 ("no tests ran") on first run. (#1321)
  The generated `tests/conftest.py` initialises the domain through a session-scoped autouse fixture instead of `pytest_sessionstart`, so a plain `pytest` / `make test` (driven by `testpaths`) sets up the domain context. The old hook only fired when the collection path passed through the package's test directory.

#### Removed

- The `logging.toml` file that `protean new` generated at the project root. Nothing in the framework read it; `[logging]` in `domain.toml` is the one config Protean loads (see `Domain.configure_logging`). (#1320)

#### Fixed

- Fix `protean new` so the generated example project initialises through a normal `domain.init()` and passes `protean check`. The scaffold previously shipped package re-exports that broke traversal, plus a projector and projection with a missing-module import, an aggregate referenced by name instead of class, and no identifier field. (#1316)
- Fix the scaffold's `.env.example`, `README.md`, and `docker-compose*.yml` to set `PROTEAN_LOG_LEVEL` instead of the unread `LOG_LEVEL`/`LOG_FORMAT`, so the documented env override actually takes effect. (#1320)

## [0.17.0] - 2026-08-04

### Added

- Fields accept a `renamed_from=` option (an old name or a list of aliases). A stored payload written under the old key deserializes into the renamed field without an upcaster, the rename is emitted into the IR, and `protean ir diff` reports a single safe `field_renamed` change instead of a breaking remove+add. (#1139)
- Events accept a `superseded_by` option naming their replacement (an Event class or a name string). Raising a deprecated event now emits a `ProteanDeprecationWarning` once per event type that names the successor, and the `DEPRECATED_ELEMENT` diagnostic reports it in the IR. (#1133)
- Opt-in lenient deserialization for legacy event/command payloads. Set the `lenient_deserialization` config key (or the per-event `lenient` meta option) so that deserializing a stored payload drops fields no longer on the current class — recording them under `metadata.extensions["_dropped_fields"]` — instead of raising a `DeserializationError`. The default stays strict (`extra="forbid"`): unknown fields raise unless lenience is explicitly enabled. Field-rename (`renamed_from`) aliases resolve first, so a renamed old key is kept, not dropped. (#1134)
- `protean check` now reports `UPCASTER_GAP`: an event whose `__version__` is N>1 but has no upcaster path from a prior version (1..N-1) to N is flagged at build time, instead of failing only at read time with a `DeserializationError` when an old stored payload is loaded. Both a total absence of upcasters and partial coverage (e.g. a v3 event with only a 2→3 upcaster leaves v1 stranded) are caught. Relatedly, an upcaster's `event_type` may now be given as a string forward reference: it resolves by name to the registered event, and a string naming an unregistered event surfaces as a clean structured error. (#1131)
- The compatibility checker is now evolution-aware. Deprecation grace (a field deprecated at or past its removal version is a safe removal) now applies to all persisted elements, including internal and event-sourced events, not only published contracts. An event version bump whose old→new path is covered by a registered upcaster chain has its schema-transformation changes (field removals, type changes, required-field additions, the `__type__` version-string bump) downgraded from breaking to safe, citing the mitigating upcaster; upcaster chains are now projected into the IR (`upcasters` section) so the checker can consult them without a live domain. (#1132)
- `protean schema generate` now emits **Avro** and **Protobuf** schemas in addition to JSON Schema, via `--format avro|protobuf|json` (default `json`). Per-version files are written as `{name}.v{version}.avsc` / `.proto`. Avro records use null-first unions for optionals and logical types for identifier/date/datetime; Protobuf messages use proto3 `optional`/`repeated`, well-known types, and field numbers assigned deterministically in sorted field-name order, so re-generating an *unchanged* schema is byte-identical. (Adding a field renumbers alphabetically-later fields — the numbers are for schema emission, not wire-compatible evolution.) (#1137)
- `protean events catalog` lists every concrete event (those belonging to an aggregate cluster) with its version, deprecation and supersession status, upcaster chain, and consumers (event handlers / projectors / process managers), sourced from the domain IR. Renders a human table or `--json`, and works from a live domain (`--domain`) or a serialized IR file (`--ir`). `protean schema generate --format all` emits the matching versioned `.protean/schemas/` tree in every format (JSON + Avro + Protobuf) in one pass — together they form the local schema-registry on-ramp. (#1135)
- `protean ir diff` now reports an **Avro-style compatibility verdict** — `BACKWARD`, `FORWARD`, `FULL`, or `NONE` — alongside its breaking/non-breaking classification, in both the text output and `--format json` (under a new `compatibility` block with per-element `avro_verdicts`). `CompatibilityReport` gains an `avro_verdict` property and an `avro_verdicts_by_element()` method. The verdict maps Protean's change classes onto Avro's rules (add-optional → FULL; add-required-without-default → not BACKWARD; remove a required field → not FORWARD; type change → NONE; a declared rename → BACKWARD, or FULL when the old field was optional or had a static default) and honors upcaster mitigation (an upcaster-covered version bump reads as BACKWARD). It matches the schema `protean schema generate --format avro` emits, which now carries Avro `aliases` for declared field renames. Visibility flips are payload-neutral for the verdict but remain breaking. The verdict is informational — the CI exit code is still governed by `[compatibility] strictness`. (#1138)
- An **"Evolving events over time"** how-to guide (`docs/guides/evolving-events.md`) walks the full v1→vN workflow on one running example — add a field with a default, rename a field with `renamed_from`, bump the version and write upcasters, deprecate + supersede an event, read legacy payloads leniently, inspect `protean events catalog`, generate JSON/Avro/Protobuf schemas, and read the `protean ir diff` Avro compatibility verdict — with real generated output and a lifecycle diagram. The `renamed_from` field option and the `lenient_deserialization` config key are now documented in the reference, and the scattered upcasting / schema-generation / compatibility docs cross-link the new guide. (#1136)
- `protean check` diagnostics now carry a richer schema: every built-in finding includes a `category` (`handler_completeness`, `aggregate_design`, `versioning`, or `deprecation`), a `rule` with a `rationale` and a `fix`, and a `suggestion`. A new per-element `suppress_checks` decorator option (e.g. `@domain.aggregate(suppress_checks=["AGGREGATE_TOO_LARGE"])`) silences named codes for a single element, and a `[lint.suppressions]` config table (`{CODE = N}`) grandfathers the first `N` findings of a code in a deterministic order so a codebase can adopt a rule without failing on pre-existing violations. Custom lint rules that emit only the minimal keys still work and default to `category = "custom"`. A malformed `[lint.suppressions]` value (non-integer or negative count) is reported as a clear configuration error on every build path rather than crashing. (#774)
- `protean check` now runs four aggregate & value-object fitness functions, all under the `aggregate_design` category. `CROSS_AGGREGATE_REFERENCE` (warning) flags a `Reference` field pointing at a *different* aggregate's root — the transaction-boundary violation of Vernon's Rule 3 — while leaving the idiomatic child-entity → own-root back-pointer and `HasOne`/`HasMany` associations untouched. `ES_AGGREGATE_NO_EVENTS` (warning) flags an `event_sourced=True` aggregate with no events, which cannot reconstitute its state. `VALUE_OBJECT_MUTABLE_FIELD` (warning) flags a value object reachable from an aggregate (embedded or via `part_of`) that has a `List` or `Dict` field, whose mutable state breaks equality-by-value. `AGGREGATE_NO_INVARIANTS` (info) nudges when an aggregate has no `@invariant.pre`/`@invariant.post` methods (own or inherited). All four honour per-element `suppress_checks` and the `[lint.suppressions]` allow-list. (#775)
- Add two bounded-context fitness functions to `protean check`. `CIRCULAR_CLUSTER_DEPENDENCY` (warning) flags every aggregate cluster whose cross-aggregate identity references make it part of a directed cycle — computed by strongly-connected-component membership, so a cluster on more than one cycle is reported exactly once and no cluster in a cyclic component is missed; the within-aggregate child→root back-pointer and any intra-cluster reference are excluded, so only genuine inter-cluster cycles are reported. `INFRA_IMPORT_IN_DOMAIN` (warning, opt-in via `[lint].check_infra_imports = true`) flags any registered domain element — aggregate, entity, value object, repository, handler, domain service, process manager, subscriber, and so on — whose source module has a top-level import from `protean.adapters`, coupling the domain layer to a concrete adapter; imports guarded by `TYPE_CHECKING`, `try`/`except`, or a function body are ignored. Both codes are in the `bounded_context` category and honour the `suppress_checks` option, the `[lint].suppressions` allow-list, and the `[lint].level` floor. (#776)
- Five handler-completeness and flow-fitness diagnostics now surface in `protean check`: `QUERY_HANDLER_WITHOUT_QUERY` and `PROJECTOR_HANDLES_ORPHANED_EVENT` and `COMMAND_HANDLER_CROSS_CLUSTER` (warnings), plus `SUBSCRIBER_NO_STREAMS` and `PROCESS_MANAGER_UNCLOSED` (info). Each flags a wiring gap or boundary violation in a projection, projector, command handler, subscriber, or process manager, and honours the existing `suppress_checks` / `[lint.suppressions]` channels. (#777)
- Add three info-level naming-convention diagnostics to the IR builder: `EVENT_NOT_PAST_TENSE` flags domain events whose name ends in `-ing` (`OrderPlacing`), `COMMAND_NOT_IMPERATIVE` flags commands that do not begin with a verb from the pinned `IMPERATIVE_VERBS` set (`OrderCreation`), and `AGGREGATE_NOT_NOUN` flags aggregates whose name ends in a verb, gerund, or adjective suffix (`OrderProcessing`, `Notify`, `Recursive`). All three are heuristic suffix/prefix checks — advisory (`level: "info"`), so they never gate CI under the default `[lint].level = "warn"` floor, and they pass through the existing per-element `suppress_checks` / `[lint].suppressions` channels. (#778)
- `protean check` gains two CI-standard output formats: `--format sarif` emits a SARIF 2.1.0 document (for GitHub Code Scanning upload and IDE problems panels), and `--format github-annotations` emits `::error`/`::warning`/`::notice` workflow-command annotations that surface findings inline on a PR without any SARIF-upload infrastructure. SARIF `reportingDescriptor` metadata is drawn from the enriched diagnostic schema (`rule.rationale`, `rule.fix`, `suggestion`); element locations resolve through the domain registry to the defining source file when available. `rich` remains the default and existing `rich`/`json` behaviour and exit codes are unchanged. (#779)
- Documented the architecture fitness functions end to end: a new [Architecture Fitness Functions guide](https://docs.proteanhq.com/guides/architecture-fitness-functions) (running `protean check`, the suppression layers, CI gating, SARIF/GitHub-annotation output, and custom rules), a [Fitness Function Catalog](https://docs.proteanhq.com/reference/fitness-functions) with every built-in rule's rationale and fix, and a [`protean check` CLI reference](https://docs.proteanhq.com/reference/cli/check) covering the flags, output formats, exit codes, and diagnostic schema. (#780)
- Add `EVENT_HANDLER_FOREIGN_EVENT` (warning, category `handler_completeness`) to `protean check`: flags an event handler whose `part_of` cluster differs from the cluster that owns an event it handles, one finding per handled foreign event. Same-cluster handling stays silent, and projectors/process managers are out of scope by design since cross-cluster event consumption is their normal job. Honours per-element `suppress_checks` and the `[lint.suppressions]` allow-list. (#824)
- Custom subscription profiles can now be defined under `[server.profiles.<name>]` in `domain.toml`. A custom profile is a set of subscription config overrides, optionally basing itself on a built-in profile with `inherits = "<built-in>"` (single level onto a built-in base). Once defined, a custom profile name is usable wherever a built-in name is: a per-handler `profile`, a handler's Meta `subscription_profile`, or `default_subscription_profile` (which resolves below the server-level defaults, so those still win over its fields). Validation is fail-fast, raising `ConfigurationError` when a custom profile reuses a reserved built-in name, sets an unknown field, or inherits from anything other than a built-in. (#827)
- Add stream retention for StreamSubscriptions: the new `retention_maxlen` config field bounds a subscription's broker stream so processed messages don't accumulate forever. After each batch the stream is trimmed. With more than one consumer group the Redis broker trims by `XTRIM MINID` at the slowest group's last-delivered position, so an entry a slow group has not yet read is never removed — but a group parked at `0-0` (a dead consumer, or a handler that was removed) holds the floor down and the stream keeps growing until that group is deleted. With at most one group the broker uses a plain `XTRIM MAXLEN`: this is a fixed-size cap, so if the lone handler falls more than `retention_maxlen` behind (catch-up on a pre-existing stream, an outage, a slow handler under a fast producer) the oldest unread entries are dropped. Trimming is approximate and size-based (no time-based TTL), off by default, and each built-in profile carries a default cap (`production`/`fast` 100,000, `batch` 500,000, `debug` 1,000, `projection` none — it reads the event store, not a stream). Custom `[server.profiles]` sections may set `retention_maxlen` too. Brokers without a persistent stream (inline) treat `trim()` as a no-op. (#828)
- Add a per-subscription circuit breaker to `StreamSubscription`. It counts consecutive handler-outcome failures and, once `circuit_breaker_threshold` (default 10) is reached, moves to OPEN and pauses reads for `circuit_breaker_reset_seconds` (default 60) so a struggling downstream stops receiving new batches. (The breaker gates reads only; messages already read in the tripping batch are still processed.) Pending messages stay in the stream for redelivery — the breaker never acks an unprocessed message. After the reset window it allows a single HALF_OPEN probe: a success closes the breaker, a failure re-opens it. Both keys resolve through the full subscription config hierarchy (server defaults, per-handler server config, handler `Meta`, profiles, `from_dict`/`from_profile`). Each transition records the `protean.subscription.circuit_breaker.state` counter and emits a `subscription.circuit_breaker.opened`/`closed`/`half_open` trace. (#829)
- Added the publishing side of `sequential_by` per-key sequential processing (ADR-0028). Event handlers, command handlers, and process managers can now declare `sequential_by`: on event/command handlers it names a field on the payload; on a process manager it is a boolean that partitions each subscribed category by that category's `correlate` field. At registration the framework validates that every handled event/command carries the named field, that a stream category is partitioned by only one key, and that the target broker advertises `STREAM_PARTITIONING` (the single-threaded inline broker is the accepted no-op exception). The Unit of Work extracts the key off each event and validates it synchronously in the caller's transaction — a null, colon-bearing, reserved-lane/DLQ, or `__name__`-sentinel value fails the caller's operation and never enters the outbox — and stores it on a new `Outbox.partition_key` field. When the broker supports partitioning, the outbox processor routes such a row to `{stream_category}:{key}` (composing with the priority-lane suffix as `{stream_category}:{key}:{backfill_suffix}`) and abandons rather than retries a row whose key is somehow invalid. The consumer side (partition ownership lease, fencing, reclaim, discovery index) is deferred to #831. (#830)
- Added the consumer side of `sequential_by` per-key sequential processing (ADR-0028), turning it on for event handlers and process managers on the Redis broker (which now advertises `STREAM_PARTITIONING`). A new `PartitionedStreamSubscription` reads every live partition stream of a category and drains each key strictly in order, with a single active consumer per partition across engine instances. The single-consumer guarantee is enforced by an ownership lease plus a fencing token (a per-partition generation), not a per-message lock: a slow or stalled owner can never let two different same-key events run at once or land out of order, and a stale owner that lost its lease is fenced out of both reading and acking. On owner crash another instance takes over at a new generation and reclaims the dead owner's pending entries (`XAUTOCLAIM`) so nothing is lost or skipped. A partition that cannot process its head message halts (no auto-DLQ, no advance past the poison) scoped to that one partition while others keep flowing. Partitions are discovered from a maintained per-category index the publisher writes (`{stream_category}:__partitions__`) — no keyspace scan — and drained cold partitions are reaped to keep the index bounded. Process managers own by correlation value spanning their subscribed categories. New broker port methods back this (partition index read/write, lease acquire/renew/release with a generation, fenced read/ack, `XAUTOCLAIM` reclaim, cold-partition reap), and the consumer timing is tunable under `[server.partitioning]` (`lease_ttl_ms`, `heartbeat_interval_seconds`, `poll_interval_seconds`, `reap_idle_ms`). (#831)
- Added a [Tuning Subscriptions](https://docs.proteanhq.com/guides/server/tuning-subscriptions/) guide covering everything the 5.2 work shipped: choosing a subscription profile, overriding a single setting versus defining a custom profile, capping stream growth with `retention_maxlen`, what the circuit breaker does when a handler keeps failing, processing events for one entity in order with `sequential_by`, and reading consumer lag from the CLI or the readiness probe. It also says which knob to reach for first when a subscription is not keeping up. The `dlq_retention_hours` and `dlq_alert_threshold` options are now listed in the server configuration reference, and a test keeps every subscription option and profile documented. (#833)
- Added a cross-adapter conformance suite for the query-API primitives (`count()`, `only()` projection, `isnull`/`lt`/`lte` lookups, `F()` column comparison, `_delete_top`, and `_claim`), so each adapter is held to the same behaviour for the capabilities it declares and divergence fails a test rather than reaching production. The contract and its capability tiers are recorded in ADR-0023. (#950)
- `protean check` now flags **`UNINDEXED_FILTER_PATH`**: a repository query that filters on an aggregate field no declared index covers, which forces a full table scan on a relational backend. The rule is the first consumer of the behavioral-analysis substrate — it joins the indexes declared on the aggregate with the fields each repository query names, read from method bodies (`filter`/`get`/`find`/`find_by`/`exclude`) across the whole package, including application-service queries whose receiver statically resolves to a registered aggregate or repository class. A field is covered when it is the identifier, a single-column `unique` constraint, or the leading column of an `Index`; a filter on a non-leading composite column, or on any other scalar field, is flagged with the call-site location and an `Index()` fix. An operator lookup such as `age__gte` is evaluated by its base field. It is deterministic and conservative — a dynamic `filter(**kwargs)`, a value-object or association field, or an unresolvable receiver (a local variable, or a `repository_for(...)` result pending dataflow) is skipped, not guessed — and suppressible per-aggregate via `suppress_checks=["UNINDEXED_FILTER_PATH"]` or the `[lint].suppressions` allow-list. See the [rule reference](concepts/protean-check/rules/unindexed-filter-path.md). (#955)
- **Breaking.** Add the `UNBOUNDED_INDEXED_STRING` build-time lint rule (category `persistence`, warning level): `protean check` now flags an aggregate field that is both included in a declared index and an unbounded `String` or `Text` — specifically a `Text` field, or a `String` declared with `max_length=None`. Such an index produces DDL that fails on SQL Server, needs an explicit prefix length on MySQL, and carries storage and performance overhead on PostgreSQL. Give the field a bounded `max_length`, or remove it from the index. The rule is scoped to an aggregate root's own scalar fields named in a declared `Index`; other string-like types (`Identifier`, `Status`), value-object attributes, field-level `unique=True`, and child-entity/projection indexes are out of scope. Because it is a warning-level rule, a domain that already declares such an index will newly report a finding (and, at the default `[lint].level = "warn"`, fail `protean check`). (#956)

- Projectors can now opt into **consume-side idempotency** with `@domain.projector(idempotent=True)`. Event delivery is at-least-once, so a redelivered event previously double-applied a non-idempotent projector (`total += 1`) and corrupted its read model. An idempotent projector records a `(message_id, handler)` marker in the same transaction as its read-model write, so a redelivery is applied exactly once on a transactional (relational) provider. Off by default; for cache-backed projections write idempotent upserts instead. See ADR-0017. (#1042)

Upgrading produces a one-time diff on the next regeneration (dropped timestamp, sorted keys); staleness and diff checks are unaffected. (#1064)

- `protean check` now detects every active framework-API deprecation. A declarative deprecation registry in `protean._deprecation` is the single source of truth: each framework-API warn site routes through `warn_from_registry`/`deprecated_from_registry`, which read the removal version and replacement advice from the entry, so a framework deprecation cannot warn without being registered (a source-scan test enforces it; a user-declared deprecated event is the one exception, since its removal comes from the event's own meta). (#1105)
- Deprecated the `is_event_sourced` aggregate option in favor of `event_sourced`. The alias continues to work but emits a `RemovedInProtean10Warning` and surfaces a `DEPRECATED_OPTION` diagnostic from `protean check`; it will be removed in v1.0.0. If both are supplied, `event_sourced` wins. (#1107)
- The `published` option on a command is deprecated and will be removed in v1.0.0. Commands are internal to the bounded context — only events participate in the published language — so the option was silently absorbed with no effect. Passing `published` to `@domain.command(...)` or `domain.register(Cmd, ...)` now surfaces a `DeprecationWarning` (`RemovedInProtean10Warning`) at command-declaration/registration time and the option is dropped; `protean check` additionally reports the usage as a `DEPRECATED_OPTION` warning diagnostic. Events are unaffected and keep the `published` option. (#1108)

  Deprecated six `protean.utils` plumbing helpers that were never intended as public API: `derive_element_class`, `generate_identity`, `fully_qualified_name`, `convert_str_values_to_list`, `TypeMatcher`, and `utcnow_func`. They remain importable through a module `__getattr__` and now emit `RemovedInProtean10Warning` on access; each is scheduled for removal in v1.0.0. Framework code uses the underscore-prefixed implementations directly and does not trigger the warning.

### Fixed

- `protean check --format sarif` now emits `helpUri`/`informationUri` links to the live documentation domain (`docs.proteanhq.com`) instead of the retired `docs.protean.io`, so the rule and tool links resolve in GitHub Code Scanning and IDE problem panels. (#780)
- Handler resilience options (`timeout`, `retries`, `backoff`, `retry_exceptions`) now appear in the materialized IR under a `resilience` key, making them visible to `protean ir diff` and the Observatory. (#1015)
- Fixed Elasticsearch database setup crashing with `KeyError` when the domain registers a cache-backed projection (`@domain.projection(cache=...)`) — the Elasticsearch analogue of the SQLAlchemy break fixed in #1034. Provider table/index ownership is now decided by a single `BaseProvider.owns()` gate, which also excludes entities nested at any depth under an event-sourced aggregate and raises `ConfigurationError` when an element references an unknown provider. (#1037)
- Fix the event-store append happening outside the aggregate + outbox transaction, which left a crash window that could corrupt event-sourced replay. `UnitOfWork` now appends events to the event store as the durable anchor of the commit, before the relational session commit, so a crash between the two stores leaves the events durable and the outbox recoverable rather than leaving the store missing a committed event. See ADR-0015. (#1040)
- Multi-step process managers now cascade to completion under `event_processing = "sync"`. Synchronous event dispatch is now breadth-first, so each handler's UnitOfWork (including a process manager's transition) commits before the next event is processed — a saga no longer stalls after its start handler, and a projector for an originating event runs before a projector for a nested event (no more `ObjectNotFoundError` on create-then-update read models). See ADR-0016. (#1048)
- Fixed `reconcile_outbox` (the ADR-0015 crash-window recovery) being a permanent no-op with the Message-DB event store. `read_last_message("$all")` returned `None` for category streams, so reconciliation short-circuited before scanning and a durable-but-unpublished event was never repaired. The Message-DB adapter now resolves `$all`/category streams (falling back to a category read, picking the newest by global position), so crash-window recovery and the engine's startup sweep work on Message-DB-backed domains. (#1073)
- Fixed a silent lost update in the SQLAlchemy adapter under optimistic concurrency. The aggregate version check was a non-atomic read-compare-write, so two concurrent transactions could both pass the check and both write, losing an update with no `ExpectedVersionError`. Aggregate models now carry a SQLAlchemy `version_id_col`, so the update flush is guarded by `WHERE _version = :expected` and a stale write raises `ExpectedVersionError`. (#1087)
- A `$all` (cross-category) event-store subscription no longer silently skips an event whose `global_position` commits out of order. Because `global_position` can be assigned across categories out of commit order (a lower value committing after a higher one), advancing the checkpoint to the last position seen could permanently miss the late-committing lower one — at zero apparent lag. `$all` subscriptions now hold at the first gap and process only the contiguous run, abandoning a gap that stays unfilled longer than `gap_timeout_seconds` (default 5, under `[server.event_store_subscription]`) as a rolled-back position. Single-category subscriptions are unaffected — they are already gap-free by the store's per-category commit-order guarantee. (#1088)
- Fix `protean server --workers N` silently double-processing events on the event-store subscription path. Event-store subscriptions read directly from the event store with no cluster-wide ownership, so every worker processes the same events. The server now refuses to start more than one worker when any handler resolves to an event-store subscription, naming the offending handlers and pointing to the three ways forward: run a single worker, switch those handlers to stream subscriptions (`subscription_type = "stream"`), or pass the new `--allow-event-store-multiworker` flag to override. The guard is enforced at both the `protean server` CLI and the programmatic `Supervisor` entry point (which gains an `acknowledge_event_store_risk` parameter). Stream-based deployments are unaffected and continue to scale horizontally, as do broker-only deployments backed by a cluster-aware broker (e.g. Redis Streams consumer groups). The guard is **per-process**: it only sees the workers within one `protean server` invocation and cannot detect a second process (another container or Kubernetes replica) reading the same event store, so a domain with any event-store subscription must run as exactly one process cluster-wide until database-backed cluster ownership is available. The production-deployment guide documents this boundary. (#1089)
  **Breaking-change classification (ADR-0004):** Tier 2 (behavioral) — a domain with event-store subscriptions and `--workers > 1` previously started (and silently double-processed events); it now refuses to start. No 3-version opt-in/warn/flip transition is applied because the prior behavior was a silent correctness bug, not an intentional default this policy protects; the `--allow-event-store-multiworker` flag / `acknowledge_event_store_risk=True` parameter is the immediate, same-release opt-out for anyone who needs the old behavior.
  **Migration:** [Smaller changes worth knowing](https://docs.proteanhq.com/reference/migration/v0-17/#smaller-changes-worth-knowing)
- Fix an event-sourced `repository.get()` not returning the in-flight aggregate already cached in the current `UnitOfWork`. The identity-map lookup indexed the map with a flat identifier key, but the UnitOfWork stores it provider-nested (`{provider: {identifier: aggregate}}`), so the documented identity-map optimization never triggered — every `get()` re-loaded from the event store, and two `get()`s of the same aggregate within one UnitOfWork returned divergent objects. Surfaced by a mutation-testing pass over the event-sourcing path. (#1099)

### Upgrade Notes

- **Outbox unique index (#1009).** If you run the outbox on a SQL store (PostgreSQL, SQLite, MySQL, or SQL Server), migrate the unique index from `message_id` to the composite `(message_id, target_broker)`: drop `uq_outbox_message_id`, backfill any rows where `target_broker IS NULL` to your internal broker name (default `"default"`), then create the composite unique index. Each domain's IR is stored under `.protean/<name>/ir.json`. The `--domain` argument is now optional when `[domains]` is configured
- Structured logging integration for automatic correlation context injection: new `protean.integrations.logging` module with `ProteanCorrelationFilter` (stdlib `logging.Filter`) and `protean_correlation_processor` (structlog processor) that read `g.message_in_context` and inject `correlation_id` and `causation_id` into every log record. New `domain.configure_logging()` convenience method wires up both the filter and processor in one call. Safe no-op when no domain context is active.

All `handler.started`, `handler.completed`, `handler.failed`, `pm.transition`, `outbox.published`, `outbox.failed`, `message.acked`, `message.dlq` trace events now carry correlation and causation IDs from the processed message metadata. Batch-level outbox spans only set these attributes when all messages in the batch share the same ID. This enables filtering all spans in a request chain by correlation ID in Jaeger, Datadog, or Tempo.

The response always includes an `X-Correlation-ID` header reflecting the ID that was used (from header, explicit `domain.process()` param, or auto-generated).

### Changed

- Documentation now positions `to_dict()` as the only recommended serialization method for domain elements and warns against using Pydantic's `model_dump()` directly, which does not handle Reference fields, shadow fields, or datetime conversion correctly. Pydantic methods are hidden from generated API docs.

- Status field self-transitions are now validated against the transition map instead of being silently allowed. Assigning a status to its current value is rejected unless the state lists itself as a target (e.g., `CANCELLED: [CANCELLED]`). This catches re-entry bugs at the framework level and makes idempotent operations explicit in the transition declaration. Terminal states also reject self-assignment.

### Fixed

- Fix unreadable handler wiring and event flow diagrams by splitting into per-concern diagrams in Markdown output (#821)
- Fix Mermaid parse errors in cluster diagrams when invariant names contain commas or are unquoted
- Fix `TypeError: can't compare offset-naive and offset-aware datetimes` in outbox retry logic. Database adapters may return timezone-naive datetimes for `next_retry_at` and `locked_until`, causing comparisons with `datetime.now(timezone.utc)` to crash and block all outbox processing. Added shared `ensure_utc_aware()` utility to normalize naive datetimes before comparison.

When no correlation ID is present, a fresh UUID is auto-generated. This ensures the cross-service correlation chain is preserved through subscriber processing.
- Preserve outer message context across nested `domain.process()` calls: `CommandProcessor.process()` now saves and restores the previous `g.message_in_context` instead of unconditionally clearing it.
